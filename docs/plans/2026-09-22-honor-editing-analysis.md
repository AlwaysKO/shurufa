## 结论

### 1. 同码换词反复出现，九宫格消歧/选词负担明确存在

BSN-AN00 检出72次严格条件下的同码换词（先上屏、2秒内删字、15秒内在同一位置重输、编码相同且词不同）。例如房价→放假（3264542）5次，得→的（3）9次，累→了（5）5次，老→了（5）3次。

北京时间9月22日15:31:39，夜不收→删除3字→也不是，均为93287；15:32:40，肩窝→删除2字→叫我，均为542696。14:51:32起，妈→码→吗均为62。

这些案例不符合“所有错误都因为数字键按错”的解释；但现有日志没有候选顺序、候选点击索引/坐标，不能区分默认候选不合适、主动点错候选或候选布局变化。

### 2. 已确认学习缺口：立即纠错仍给原词正向加权

ImeService 两个 commitText 入口在宿主接受后立即 OfflineT9Candidates.learn；LocalInputStore.learn 增加 count 与衰减权重+1。删除入口仅记录编辑，不撤销对应选择。原9月18日基线和当前代码都存在此机制。

线上该设备词库备份可见：3264542的房价与放假各count=5，权重均约4.54226；542696的肩窝与叫我各count=4，权重均约3.999；93287的夜不收与也不是各count=2。不能把这些词永久归为错词，但明确的纠错操作未排除对先前选择的奖励。

PersonalCandidateRanker 使用基础顺序先验+学习权重（半衰期14天）。如果原错选词基础顺序较靠前，而每轮两者都+1，反复纠错不能有效拉开两者的学习权重。这是会持续增加纠错负担的机制缺口；未还原当时手机完整候选表，因此不宣称每个实例的第一候选位置。

### 3. 进一步确认：1～2键短码不参与应用层个人学习/重排

用户要求继续分析后，对照了旧9月18日基线与当前实现：LocalInputStore.validCode 只接受3～30位数字码；OfflineT9Candidates.select 也仅对3～30位数字码进入个性化链路，1～2位直接返回原生候选。

BSN-AN00的带码上屏中，1键212次、2键393次，合计605次（3088条带码上屏的19.6%）。严格同码纠错72次中，1键19次、2键12次，合计31次。得→的（3）9次、累→了（5）5次均属于被跳过范围。dictionary_entry中该手机的数字码choice最短为3位，没有1～2位记录，与实现一致。

这是应用层新增学习的覆盖缺口，不等于Rime引擎自身完全不学习。也不能把短码中反复换字全部归因于前述错误加权：1～2键在这条持久化路径上根本没有加分，应分别处理。

修复若实施，应只在短码原生合法候选中重排并保留原生索引，不顺便扩大长词补全、跨码召回范围。验证目标是常用目标字更容易再次选到，而非仅看云端出现记录。

### 4. 短码和尾音不完整增加候选歧义，不能全部归咎用户

BSN-AN00 的3088条带码commit中，1113条码长<=3（36.0%）；对比设备1993条中542条（27.2%）。上报码是最终选择关联的码，包含简拼、分段等用法，不是逐键触摸轨迹。

例：北京时间16:44:00，先提交就任（548736），立即删任，再提交扔（7364）。这体现ren/reng尾音补全的区别；仅凭最终码无法判断是用户漏键、引擎补全还是选词时机。

应用层个人排序没有当前句子上下文参数，主要按码与词历史重排；不能期待新增词条数量本身解决所有同音/同码歧义。

### 5. 版本差异是混杂因素，不是硬件结论

查询时BSN-AN00注册版本20260918.22，ELI-AN00为20260922.15。device.app_version是最近注册信息，事件不附带每次构建SHA，不能将窗口内所有事件精确绑定同一个包。9月22日源码已有短码召回、分段学习和锁音重排修复，不能视为旧包已获得这些修复。

没有触摸轨迹、按键命中框、渲染时延及候选快照，无法认定荣耀X80硬件兼容性、屏幕误触或键盘卡顿。

## 建议修复顺序（未实施）

1. 优先加入有边界的纠错学习：只撤销能与本次上屏明确对应的临时奖励，保留已有有效次数和词条；修改句子、长时间后删字、发送清空不能自动视为错误。涉及本地/备份同步时维护幂等，不删手机已有词、不伪造点击。
2. 补齐1～2位数字短码的应用层学习/原生候选内重排，保留编码隔离与原生索引。以这里发现的同码纠错类别构造合成回归样例，验证纠错后再次输入的候选实际改善；不要把真实聊天原文塞进测试夹具。
3. 在包含既有短码/分段修复的同版本包比较两台体验，再判断是否需要机型布局适配。单纯统一版本不能保证解决错误学习问题。
4. 如仍有误触怀疑，在用户主动测试时增加最少的候选顺序/选择来源/耗时诊断，而非依据后台文本猜测触摸问题。
