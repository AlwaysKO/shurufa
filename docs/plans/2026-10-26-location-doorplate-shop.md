# 定位门牌与店名实现计划

**目标：** 定位列表和地图弹窗新增门牌号、店名；地图缺失或无法确认时显示未确认，不把最近店铺当作所在店铺。

**方案：** 用户已确认先按上述方式显示，沿用现有Nominatim兼容服务，不引入Key或手机采样。逆解析细化至建筑级并请求几何；门牌由道路+house_number组成。店名仅接受商店或餐饮等经营类对象，且服务返回的Polygon/MultiPolygon必须覆盖定位坐标；仅附近节点、道路名称、楼宇名或无几何证据均不认定店名。匹配仅说明地图坐标对象，不证明实际到访或消除原定位误差。

**技术：** PostgreSQL JSONB、TypeScript/Express、Vue3。当前分支原地，不提交、部署或改Android。

1. 测试先行：覆盖门牌、店铺面覆盖、仅附近店铺/道路不能填名、孔洞/多面、相邻坐标不能复用11米粒度店名；验证旧地址也补详情，用户隔离与坐标/时间不改。
2. 迁移053增加location_track.place_details，保存解析成功的空结果，防止未确认无限重查；本地执行并核验。沿原串行限速、失败退避、缓存与懒解析，不全库回填。
3. API读取详情并为地点提供独立解析状态；已有地址保留。列表两列、地图弹窗同步展示，未解析细节沿现有轮询更新，失败保留退避。
4. 运行geocoder/API/前端定位测试、前后端构建；独立代码审查。只使用合成坐标样本，不上传真实坐标给公共服务验收；不自动部署。
