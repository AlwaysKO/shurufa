# 新增推荐图下载延迟修复

目标：输入命中现有说法后，新上传图能逐张显示，持续有数据的大 GIF 不因小接口的总超时而反复丢弃。

证据：真机 20260923.21 开关启用，冷静组包含新增 sticker-40、sticker-10 及4旧图；最初两新图均无原件，随后46,919字节的小图缓存成功，992,491字节大图仍缺失。使用相同手机身份读取线上两文件，HTTP200，内容 SHA 均与目录一致。历史手机 GET 大图日志只传输687,782字节。源码所有请求 callTimeout30秒，当前目录命中分支串行下载，全部结束才二次发布。尚不把源码推断当作真机超时异常实测。

方案：保持目录请求30秒，原图请求允许2分钟总时长但保留读取停滞超时；单次前台匹配最多2个下载并行，每张完成后在订阅协程更新已校验列表并保持后台排序。取消订阅不取消同作用域的原件预取，但旧订阅及旧目录不能发布。后台半小时探测/Wi-Fi/24张批次/2分钟任务边界不变。不关闭 SHA 校验、不修改素材、不改变候选文字或聊天发送。

验证：先写失败用例，覆盖大图持续传输超过30秒、慢图不阻塞快图展示、次序、取消订阅后落盘和旧目录隔离；运行同步/缓存/后台相关测试，构建原签名APK并校验。当前分支原地修改，不提交推送、不自动安装。Mac只能交付本地apk目录，Windows E盘不可达。
