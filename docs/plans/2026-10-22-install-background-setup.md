# 安装后的后台运行配置

**目标：** 用户已选择“电脑安装自动处理，并在手机首次启动集中引导剩余设置”。减少寻找系统设置和重复配置，不承诺 ROM 永不撤销授权。

**方案：** 电脑端提供显式安装入口，校验原签名、交付包和目标设备，保留数据覆盖安装；成功后只为实际安装的包添加电池优化豁免并回读。用户后续明确修订：安装后缺设置才提示，已完成后续覆盖安装不弹。手机设置页在隐私确认、输入法启用后读取真实电池/无障碍状态，结合厂商启动设置的手动确认；缺项时按实际lastUpdateTime每次安装最多自动展示一次，完成则不展示，其他设置保留手动入口。展示无障碍授权与连接分别状态，系统拒绝跳转时回退可见设置入口。厂商状态无法读回时明确标为需手动确认，不伪造已配置。

**边界：** 不新增或自动开启聊天/定位/录音采集，不写无障碍授权。用户后续允许操作手机系统设置；不据此安装新包或重启验证。只读权限状态，不高频守护、不强行停止、不卸载/清数据、不改用户主动关闭的无障碍选择。当前分支原有定位、GIF等改动保留，不自动提交推送。

## 实施与验证

1. `android/YuyanIme/tools/install_with_setup.py` 和 `test_install_with_setup.py`：先失败测试覆盖多设备拒绝、安装失败不改设置、单包豁免回读、无强停/卸载/授权命令；复用 `verify-delivery-apk.py`，安装失败和配置未完成分别报告。
2. `ui/setup/BackgroundSetup.kt`、`BackgroundSetupActivity.kt` 及对应测试：先验证一次引导状态、真实权限重读、版本升级不重置、品牌跳转拒绝后回退；UI明确区分授权与连接，不将打开设置视为设置成功。增加 Manifest 声明、设置页首次入口及“其他”永久入口。
3. 通过定向 Python/Android 测试与编译；审查安装失败路径与用户选择保留；构建、原签名校验并交付唯一 APK。当前手机游戏暂停授权仍有效，不用实机安装冒充测试。
4. 更新安装说明和项目长期规则：电脑自动配置必须通过新的安装入口，普通 Android Studio Run 不会自动执行该脚本；手机安装依赖首次引导。
