# 输入状态误建会话修复计划

> 按 Superpowers systematic-debugging、writing-plans、test-driven-development 和 verification-before-completion 执行。用户授权当前分支修复，保留所有既有修改，不自动提交、推送或安装。

**目标：** “对方正在输入/輸入…”不保存、不上报、不创建联系人会话；状态期间减少重复截图检查，恢复正常标题后仍可采集。

**依据：** 2026-09-27 只读查询线上数据发现最新错误记录的 observed_title 为“对方正在輸入...”，external_key 为 screenshot-v2:truncated:UUID。现有函数只匹配“对方正在输入”，因此繁体 OCR 绕过过滤，进入截断名称分支。状态检查继续接受每次页面变化，后台也无状态截图兜底。

**方案：** 仅对固定输入状态识别简繁字形，不转换正常联系人名。端侧复用已有各入口过滤；已确认输入状态的同一页面最多每 3 秒重新检查一次，将末次请求合并延后，正常首图无冷却。后台入库前过滤状态截图，成功确认处理，避免旧客户端无限重传。历史聊天不自动删除或模糊合并。

## 执行与验证

1. 扩充 WechatTitleStabilizerTest、WechatPendingRecoveryTest、PeerTypingCaptureTest 的繁体状态夹具；运行证明现有代码失败，再修改 ConversationTitle.kt 的固定状态识别。验证真实长名、普通正文和标题恢复不受影响。
2. 为 ScreenshotUpdatePolicyTest 增加可控时钟测试：状态检查间隔、导航清理、正常首图和恢复无延迟。在 ScreenshotUpdatePolicy.kt 和 PassiveChatAccessibilityService.kt 实现同页请求延后合并，保留末次变化。
3. chatRepository.test.ts 验证旧版简繁体状态截图不建会话、不请求缺失素材、混合批次保留正常消息、正常正文不误拒绝；chatCapture.test.ts 验证 HTTP 成功应答。最小修改 chatRepository.ts，运行 API/仓储测试与 TypeScript 构建。
4. 回归相关 Android 采集测试，独立代码审查；Android 改动完成后打原签名 APK，核验版本、签名、SHA256。当前仅连接模拟器，真机验收和线上发布明确区分。

**范围：** 本次聚焦用户指出的输入状态；“关注 朋友 推荐”等其他页面需独立核实结构，不以文字黑名单扩大本次过滤范围。

## 验证结果

- 修改前：线上繁体夹具触发 Android 3 项断言失败，后台 4 项断言失败，证实状态误识别及错误会话入库。限频新接口测试首次编译因接口不存在失败，随后实现并验证。
- 修改后：Android 12 个相关测试类共 129 项通过，0 失败/错误/跳过；覆盖状态不落盘上报、正常标题恢复、真实长名、通知入口、列表去重和正常首图。服务级测试验证连续 100 次状态请求只触发首张物理检查，3 秒后仅一次回调且恢复标题可保存；导航重置后旧回调取消。
- 后台仓储与 API 共 22 项测试通过，TypeScript 两项构建通过；过滤先于会话创建及素材查询，HTTP 200 确认丢弃旧状态截图。普通正文中包含状态文字不受影响。
- 独立只读审查未发现阻塞缺陷；建议的服务级末次请求/导航取消测试已补齐通过。
- 不修改候选词排序、输入引擎或全局截图首采规则。原有未提交的表情同步性能修复和后台 10 MiB 修改均保留。
- 此次仅只读查询线上，不删除历史记录、不修改线上数据库、不自动部署；ADB 只见模拟器，尚未真机验证。
