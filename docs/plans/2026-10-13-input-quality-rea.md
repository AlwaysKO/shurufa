# 输入质量与 REA 搜狗对照实施计划

> 使用 Superpowers writing-plans、TDD、systematic-debugging 和 verification-before-completion。用户已批准方案，当前分支实施，不自动提交、切分支、安装或发布。

**目标：** 改善未学习状态的常用候选、锁音补全、纠错和联想；保护提交、退格、分页、个人习惯与输入延迟。

**架构：** 保留 Rime 引擎。先建立受按键与明确音节共同约束的候选路径，统一召回与过滤，再依据实验决定公共排序与纠错、联想的最小改进。REA 分析搜狗实际 APK，区分静态事实、推断和无法恢复的模型能力，不复制搜狗私有词库或模型。

**技术栈：** Kotlin、Rime JNI、JUnit/Robolectric、Gradle、REA CLI/JADX。

## 任务1：REA 实际分析搜狗
1. 只读定位本机/已连接设备的搜狗 APK，保存版本、SHA256 和来源；不读取个人输入数据库，不切换应用。
2. 固定 REA CLI 版本与 JADX 引擎，运行 package/class/method 分析，保存原始输出到忽略的 .runtime。
3. 定位按键/拼音约束、候选获取、纠错/预测入口及 native 边界；结论须引用方法与证据，明确未观察到的运行行为。
验证：至少一条真实目标 APK 的 REA 成功结果；失败与功能边界如实记录。

## 任务2：锁音召回与状态一致性
文件：inputmethod/data/KeyRecordStack.kt、inputmethod/RimeEngine.kt、data/completion 下必要的匹配/候选类及对应测试。
1. 添加失败测试：nan + s 的末音节补全、已锁音节排除异读词、未完成音节/数字混合、已选汉字段隔离、失败替换不残留锁音、退格恢复。
2. 运行 :yuyansdk:testOfflineDebugUnitTest 对应测试，先确认行为失败。
3. 最小实现明确输入约束与本地候选补充；保留原生索引、选词/提交与分页约束，不用显示 preedit 猜实际锁音。
4. 重跑失败测试及 inputmethod/completion/提交状态回归。
验证：南山可补全且正确提交，锁音不被数字同码覆盖，失败替换和退格不会破坏原状态。

## 任务3：常用排序、纠错与联想
1. 建立多词对照，区分召回缺失与排序差；测试未学习、重复学习、偶选、明确纠错、人名可找性与不同读音隔离。
2. 在现有评分上做经过失败用例证明的最小修改；参数不能只针对南山调节，不用冷门黑名单。
3. 对错键与联想分别做正反例；缺少可信输入证据时不自动改写或扣历史学习。
验证：首选/前三命中、误纠正、候选耗时与旧回归；不以单词改善声称达到搜狗整体效果。
