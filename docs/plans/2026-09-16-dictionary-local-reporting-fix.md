# 个人词库本地上报修复计划

**范围：** 用户安装新版后本地后台无个人词库数据。只修传输链路，不改候选/学习算法，不清空手机或服务端旧记录。

## 已证实原因

1. `DataCollector` 只在 `target == ServerConfig.baseUrl` 时执行个人词库同步，且固定单实例指向线上。
2. 本地在线 API 已有新路由，但实际库未应用016迁移，探测500报 dictionary_lock 不存在。本轮仅事务执行016后，未带词库凭据探测返回401，保留旧表。
3. WSL ADB 无设备，项目配置的 Windows ADB 有已授权真机。重启后 reverse 为空。本轮按既有项目脚本恢复3000→Windows3001→WSL3000，触发已启用的后台同步后，本地 device.last_seen 更新。

## 最小修复与测试

- 每个当前配置目标独立个人词库同步实例，分目标保存上传hash/时间/序号/凭据；线上复用此前凭据，避免升级后身份冲突。
- 数据向两个目标分别上报；只有选定的主后台可下载/应用/确认决策。镜像只上传，不能覆盖主后台状态。主后台选择已向用户询问；未答复前保留线上主控，不擅自变更。
- 同一实例已有同目标互斥；不同目标成功与失败不互相阻塞，沿用现有生命周期、同意开关和IO调度。
- 先写 MockWebServer 失败测试：镜像仅注册/上报；本地失败重试不影响线上已确认上传；升级保留原线上凭据；本地和线上缓存彼此独立。
- 然后实现并跑个人词库、事件投递、ServerConfig和候选回归；构建测试APK。本轮手机当前已装2026091613；不以旧包的事件恢复冒充新词库端到端通过。
- 用真实本地数据库计数与API鉴权检查验收部署状态；真实词条内容和凭据不写日志。代码/构建/安装/真机同步分别报告。
