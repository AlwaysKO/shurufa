# 聊天采集通话状态过滤

**目标：** 不再上报截图中的“语音通话中”，同样处理“视频通话中”，保留正常语音消息和真实聊天正文。

**根因：** NotificationParser 将通话状态映射成 VOICE/VIDEO 并请求截图；服务端按 5 分钟窗口去重仍保留状态，不能实现不上报。

**实施及验证：**
1. 先修改通知解析和服务端测试，复现旧逻辑仍接受状态。精确匹配两种状态文本，限定支持的聊天 App、通知来源；MessagingStyle 明确聊天消息保留。
2. 通知入口直接忽略且不请求补截图；CaptureApi 与 EventDelivery 共用过滤，涵盖两级旧队列。混合批次保留正常消息，失败可重试，全状态批次取消待传且不发消息 HTTP。
3. 服务端入库前过滤旧版上报，不创建空会话、不索要素材，正常回执避免旧设备无限重传。保留服务器历史，不修改其他通话状态去重行为。
4. 运行通知、上传、事件投递 Android 回归和服务端聊天回归/构建，代码审查，生成原签名 APK。

本轮原地保护所有已有改动；不提交、推送、自动安装或部署。不触碰已确认的截图 Wi-Fi/熄屏约束。
