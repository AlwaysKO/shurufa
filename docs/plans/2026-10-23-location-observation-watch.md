# 静止省电与移动定位失联兜底实施计划

> 使用 Superpowers writing-plans / executing-plans / test-driven-development，当前分支开发，保护其他会话的未提交修改。

**目标：** 正常定位条件下争取移动时15分钟内保留有效点，静止不新增重复报告；晃动不能反复重置GPS尝试。只做本地实现/验证/打包，不连接手机或线上，不承诺无信号或系统停止服务时一定有真实坐标。

**架构：** 用“最后一次独立有效定位观测”而非最后上报时间驱动恢复。新鲜的静止点也刷新观测时间，但不上报。静止采样状态下，观测过期10分钟且距上一探测开始至少10分钟时，启动单次最多120秒的确认。持续新鲜静止观测推迟兜底，不因无上报额外开GPS。传感器/单次未确认位移只提供核实机会，同样受10分钟尝试间隔约束；真实位移一旦通过原确认门槛，可随时恢复原移动采样。用单次有界检查替代上一版密集两次补试；无有效结果时保持10分钟起始间隔的低频机会，不永久等待新外部事件。

**计时：** 用单调观测时间，缺单调时间戳时从收到回调的elapsed减去定位年龄推算；不能用择优/IO处理时间刷新旧观测。过期确认按原始截止结算；迟到唤醒如已满足再次探测条件，当次直接启动一个新的120秒窗口，不补执行过去窗口、不连续突发。GPS移动租约的迟到退避也从原截止计算，一次唤醒最多启动一个窗口。沿用原Handler+elapsed报警，不新增精确闹钟权限、常驻唤醒锁或系统权限绕过。

**方案选择：** 继续叠加密集重试会增加床上晃动/室内无信号场景耗电；只依赖运动事件仍有漏触发后的无限空档。采用新鲜度驱动的低频检查；静止时系统无定位回调，也需要偶尔检查以免永远不知道何时出发，这不产生静止上传。

**技术：** Kotlin、LocationManager、AlarmManager、JUnit/Robolectric。
