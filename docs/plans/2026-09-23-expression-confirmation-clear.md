# 推荐图确认发送后清空输入实施计划

**目标：** 用户在本次微信推荐图确认框点击发送后清空原输入；取消、返回、准备失败、新输入及切换目标均不清空。

**方案：** 用户已启用现有无障碍服务。复用其窗口/按钮事件，新增仅存于内存的本次交接状态。交接前绑定原编辑节点和文字；识别带完整发送标题、发送/取消按钮的宿主弹框；仅明确点击对应发送按钮后，核对原节点及文字未变化并清空。不以弹框消失、延时或键盘恢复推断发送，不自动点击发送，不变更 GIF 交付协议。现有直接发送路径保持独立。

**步骤与验证：**

1. 读取真机确认框结构和按钮事件，确定可用的窗口/节点身份；只读，用户操作发送/取消。
2. 测试先行：交接不清空、确认只清一次、取消/返回不清、过期/重入/目标或文字变化不清。再实现最小状态机。
3. 将状态机接入 InputView 交接与现有无障碍服务，验证真实窗口隐藏不会丢失待确认状态；图片准备失败会撤销，临时观察与聊天采集开关分开，不持久化输入正文。
4. 运行状态机、Android 事件适配、InputView 发送、GIF sender 回归，独立审查边界。
5. 生成原签名 APK，检查非 testOnly、版本、校验和并交付本机 apk/。真机安装、确认发送与取消由用户操作；不能以单测代替真机验收。

保留当前 main 和现有未提交文件，不创建分支、不提交或推送。

## 代码阶段结果

- 新增 `ExpressionConfirmation` 和 `WechatExpressionConfirmation`，在微信私有命令交接前绑定原编辑节点和完整文字快照；现有无障碍服务独立观察本次弹框，不要求启用聊天采集。
- 确认仅接受已绑定弹框的明确“发送”点击；原输入改变、其他点击、取消、其他窗口、节点失效、服务中断均保留文字。窗口恢复本身不确认，只允许 300ms 事件乱序宽限；清空前消费凭据以避免重入重复。
- 原节点无法取得/刷新或文字无法验证时，不清空。节点和原文仅存内存，最多120秒，明确确认后的清理尝试最多2秒。
- TDD：新状态机首次2项失败；审查提出的改写后恢复原文、返回迟到点击、其他窗口同名按钮均补了失败测试后修复。Android适配测试覆盖原节点失效、密码输入、取消、迟到、重复、拒绝清空、真实窗口切换及300ms内事件乱序。
- 最终155项定向回归通过，0失败/错误/跳过。完整首轮另有一项既有InputView“拼音替换成呢”失败，在暂时使用HEAD原Sender/Service的同测试中复现，补丁已恢复；另外SDK29/33/34的3个测试实例因本机缺运行库失败。最终定向运行明确排除这4个实例，不声称完整测试集通过。
- 代码审查的错误窗口同名按钮、原文改写后恢复、返回迟到事件问题均已修正并复核。
