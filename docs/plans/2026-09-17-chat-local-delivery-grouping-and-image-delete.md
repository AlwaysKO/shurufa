# 本地补传、微信截图分组与单图删除

## 现场证据

- 荣耀 ELI-AN00 已通过 Windows ADB 的 USB transport 连接，电池状态显示 `USB powered: true`，但系统 `USB_STATE` 没有 `connected/configured`，导致端侧门控在健康检查前直接拒绝本地上传。手机队列中本地目标 `attempted_at` 全为 0。补做 reverse 后又确认 Windows `127.0.0.1:3000` 不能直接到达 WSL API；必须使用项目已有的 Windows 3001 中继。原 `start.sh` 只在启动瞬间建链，手机稍后插入或拔插后不会恢复。
- 线上已有截图来自微信空无障碍树兜底。该路径固定使用 `externalKey=empty-tree-visible-chat` 和“微信当前聊天”，因此不同群和联系人必然合并，不是后台列表渲染问题。
- 当前后台只支持删除整个会话，没有单个消息资源解绑和孤儿文件清理接口。

## 实现

1. 本地门控仍要求“物理 USB 证据 + `/health` 成功”。物理 USB 证据优先使用 `USB_STATE connected/configured`，荣耀缺失该广播时允许 `BatteryManager.BATTERY_PLUGGED_USB` 兜底；无线调试且未插 USB 仍不能触发。`start.sh` 每 5 秒检查一次 ADB，手机晚接入或重连后自动恢复“手机 3000 → Windows 3001 → WSL 3000”。
2. 微信空树截图在端侧使用打包的 ML Kit 中文识别模型，只识别截图顶部标题区域，不识别或上传额外聊天文本。标题规范化后生成稳定会话键；群名尾部成员数不参与键，避免人数变化拆组。识别失败时使用标题区域视觉哈希隔离，不再把全部截图放进一个占位会话。
3. 后台新增“消息-图片”级删除：事务内只解绑所选图片；无其他引用时删除媒体记录和文件；截图消息失去最后一张图片且没有正文时删除空消息。不得删除同消息其他图片、其他消息共享图片或整个会话。

## 验收

- JVM 测试覆盖荣耀 USB 供电兜底、无线调试拒绝、标题选择/规范化及群人数变化稳定键。
- API 测试覆盖单图解绑、共享资源保留、空截图消息删除和跨用户拒绝；网页测试/构建覆盖单图删除按钮。
- 真机已安装新 APK，并在 Windows 中继及 reverse 恢复后观察到本地目标由 144 条降至 72 条，本地数据库新增至 8 个会话、28 条消息、15 个媒体资源，证明补传已实际发生；剩余队列继续分批发送。标题 OCR 和不同会话分组仍必须以用户实际打开两个不同微信会话后的画面验收，单元测试不能替代。

## 2026-09-17 群名 OCR 修正

- 用户实测同一群被识别成 `一起加油！噢力给！(6)8` 和 `一起加油!噢力给!` 两个会话。原因是群人数 `(6)` 后又多识别出一个孤立数字，并且全角、半角标点直接参与旧哈希。
- 群人数清理现允许末尾 1～2 位 OCR 游离数字随括号人数一起移除；稳定键生成前做 Unicode NFKC 规范化，显示名仍保留原有可读标点。对应回归测试使用本次真实错误标题。
- 本次再次检查时 Windows ADB 返回 `no devices/emulators found`，所以 10:37～10:38 已经在线上出现的截图没有同步到本地不是新的截图触发失败；主机没有 USB 调试通道时，`start.sh` 的 watcher 也无法建立 reverse。重新连上后需以 `adb devices -l` 出现 `device` 和手机 `/health` 成功作为本地补传判据。
- 10:54 覆盖安装后再次实测荣耀把无障碍设置清为 `null / 0`，导致随后“一路江湖”消息没有生成截图。11:04 安装最新包后已通过 ADB 恢复并确认服务 Bound；开发机新增显式 `AUTO_ENABLE_CHAT_ACCESSIBILITY` 选项，启用时由 `start.sh` watcher 在每次 USB 重连/覆盖安装后恢复服务，同时保留其他无障碍组件。普通 APK 仍不能自行静默开启。
- 后续“一路江湖”群名又出现 `一路江湖(210)A`，确认人数括号后也可能有 1～2 位 ASCII 字母 OCR 尾巴；现与数字尾巴一样随人数后缀移除。最终交付口径是：最后一次安装后用户手动开启一次无障碍，正常使用及重启由系统维持；卸载、清数据、后续覆盖安装或系统撤权后，Android 不允许普通应用自行强开。
- 用户反馈长聊天截图底部消息被截断。根因是荣耀空树兜底在没有键盘窗口时仍固定只保留窗口高度的 90%。现改为：有系统键盘时裁到实际键盘上沿；无键盘时保留完整微信窗口底部，允许带上微信输入栏以换取完整末条消息。
