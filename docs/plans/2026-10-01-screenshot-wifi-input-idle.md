# 截图 Wi-Fi 停手即补传 Implementation Plan

> **For Claude:** 使用 systematic-debugging、brainstorming、executing-plans、test-driven-development、requesting-code-review、verification-before-completion。当前分支修改，保留并发改动，不自动提交、部署或安装。

**Goal:** 查清已连接手机的聊天/导航截图是未生成还是未上报；按用户新要求取消熄屏限制，仅验证可用Wi-Fi且不打字时后台补传。

**Architecture:** 修改共享ImageUploadRuntime与CaptureUploader的熄屏门禁；保留输入3秒空闲、开始输入取消、Wi-Fi绑定逐块检查和持久重试。用户追加亮屏慢、熄屏快：每8KiB块现读屏幕，亮屏32KiB/s、熄屏512KiB/s，预算8/32MiB每分钟、间隔3/1秒；准备和截图上传分别最多一个，避免慢上传挡住新截图。沿用现有后台循环、网络唤醒和系统Job，不另造采集器或绕过系统权限。

**Tech Stack:** Kotlin / Robolectric / ADB只读诊断 / SQLite / 线上PostgreSQL只读查询。

## 已明确设计

- 用户明确取消“必须熄屏”，亮屏且Wi-Fi、停手时可上传；开始打字、断Wi-Fi、撤回同意仍中止，待传保留。此要求取代AGENTS中2026-09-30的保守熄屏策略。
- 共享规则覆盖微信/QQ/抖音截图、导航截图、已有两级待传队列。不扩大到蜂窝或USB镜像，不修改截图触发、去重、历史记录。
- 当前源码已含截图积压1秒小步检查、3秒输入空闲和网络/持久入队唤醒，系统Job仍负责进程退出后重试；不将操作系统调度延迟承诺为零。

## Task 1：证据

- 核验ADB手机版本、开关、网络、亮屏状态，读取capture.db/local_input.db副本只输出统计；导航只读取ID/时间/图片字节长度，不输出聊天正文/位置。
- 查本地原图存在性、两级待传数量/时间/重试，以及同设备线上最近成功记录，区分采集和上传。
- 手机最初ADB不可见，用户重连后已恢复；安装20261001.00（02:17更新），导航待传目录已存在。

## Task 2：TDD变更

- ImageUploadRuntime去除屏幕状态门禁与亮屏取消，CaptureUploader去除转存前熄屏门禁；保留全部输入、网络和限额守卫。

## Task 3：验证与交付

## 用户追加与审查修订

- 用户明确“熄屏后可以快速上传，亮屏时慢慢上传，只要不影响app使用和打字体验”，补两档动态速率，不恢复强制熄屏门禁。
- 亮屏慢传最大JSON可能超过旧90秒超时，统一5分钟call timeout覆盖8MiB按每8KiB暂停256ms所需的约262秒加余量；输入、网络、同意的取消仍有效。
- 审查指出共享busy使慢上传长时间阻塞新截图，新增失败测试后拆preparing/uploading独立幂等许可，仍各最多一个，输入忙都拒绝。
