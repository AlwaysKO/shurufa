# 九宫格音节输入中途的显示修复

**目标：** 用户报告“我当时想输入”打到 s 出现键帽字母组，继续 h 后消失；输入中途也必须保留全部按键对应的拼音显示，不再展开 MNO/PQRS 等标签。

**根因与证据边界：** 当前 `T9Spelling.displayComposition` 把候选未覆盖的数字直接展开成键帽列表；显示是否正常依赖每一帧原生候选是否有可完全对齐读音。手机 ADB 当前不在线。独立开源 Rime 1.11.2 的19步对照有完整 s/sh 读音，未复现手机那一帧缺读音，不能将它当成 APK 原生复现。

**最小设计：** 保留候选实际读音优先，只替换显示函数的残余按键兜底：复用既有 T9 拼音表，在完整音节和末音节前缀间切分，优先减少无法解析的按键、再减少分段数。无法组成拼音的按键保留等价的小写键代表字母，不删除、不扩写、不展开键帽列表。九宫格有多种同码读音，无候选时此显示只是可行拼读，不声称猜中用户具体字母。

只改 `T9Spelling.kt` 与 `T9PinYinUtils.kt` 的显示辅助；不修改 candidate allows/preedit、整句资格、排序、提交、学习或字体。显示中的末尾首字母不使候选内部简拼合法，也不代表原始未消费按键已经可上屏。

## 实施与验证

1. 新 `T9TransientPreeditTest.kt` 和真实 DecodingInfo 显示链路测试，先红：s/sh 前进、退格、重新输入、候选暂空、已有首选读音优先、全部码可还原。
2. 实现显示兜底，严格保留每个输入按键；既有完整读音原样保留，不引入显示缓存。
3. 旧“键帽字母组是期望输出”的断言按本次用户反馈取代；保留原始提交残码/门禁与候选边界断言。
4. 运行旧输入回放、整句/学习/UI测试；对305组候选结果要求与 .23 全字段一致。构建与签名核验，不自动安装、提交或操作聊天。当前缺少真机时明确报告。
