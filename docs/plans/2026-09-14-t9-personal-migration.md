# 个人词迁移与学习链路修复计划

目标：落实用户本轮批准的自动可读词典迁移，并先修复已有证据的独立召回/分段学习。语义过滤单独实验，不把新阈值直接装进生产。
架构：首次启动后台读取公开 UserDictionary，读取不到记录原因跳过；LocalInputStore 增量保存来源和可靠读音，不伪造选择次数。RimeEngine 保留分段候选的读音与最初完整编码，最终宿主成功提交才写入学习。个人词独立参与召回，沿用拼写/分页/上传保护。
技术栈：Kotlin、SQLite 增量表、ContentResolver、Robolectric/JUnit。

1. RED：新增个人词在原生空候选下的完整码/末字前缀召回、数据库重开、内部简拼不传播测试；分段读音/整句编码及失败提交测试；自动导入的有数据、权限拒绝、重复运行、不增加真实次数测试。
2. 实现：LocalInputStore 升级版本 4，只新增 personal_word 元数据表；旧表不重置。个人读音不符合文本长度/编码时拒绝独立召回。
3. 实现：SystemDictionaryMigration 只查询 content://user_dictionary/words；后台运行一次，记录状态/统计，捕获不可访问情况，不扫描其他输入法私有目录。非中文/无可靠读音不假装能九宫格还原；原词来源保留，未知读音等待原生实际读音。
4. 实现：T9CommitTracker 分段累计，RimeEngine 与两条 ImeService 上屏路径传递读音；编辑/取消清理，无成功上屏不记次数。
5. 运行相关回归，并做代码审查；不覆盖其他会话改动、不安装或提交。语义过滤仍以已有坏例/短句基线为门禁，另行验证后才变更。

## 实施记录（2026-09-14）

本轮授权：用户要求“安装时自动读取能读到的旧词库，读不到另说，并开始改规则”。实际生命周期为安装后的首次进程初始化；安装器安装 APK 时不执行应用初始化。

### 已实施的代码范围

- 数据库版本 3 → 4，仅增加 `personal_word` 及编码索引；保留旧次数、衰减权重、待上传报告。词条以文字/完整读音/来源去重，导入不写 `learned_input`，不产生上传事件。
- 首次初始化后台尝试系统 `UserDictionary`，声明其读取权限和 provider 可见性。记录 `complete / permission_denied / unavailable / failed` 和导入词数；失败不冒充成功。读取不到不阻塞输入法初始化，不扫描其他应用私有目录、不读取聊天/剪贴板、不上传导入内容。
- 迁移读音由本地已收录读音或经过逐字拼音表校验的显式 shortcut 提供；任意英文快捷码不是拼音。未知读音仅保存原词，**导入数量不等于全部已可九宫格召回**。未迁移其他输入法私有历史、排序模型或账户数据，公共词频也未换算成本机点击次数。
- 限制单次 50,000 行，provider 查询使用 5 秒取消信号；词库按导入词集合批量扫描，数据库先提交再记录状态，重复启动不重复计数。
- 已学习且有可靠读音的个人词独立召回，不再依赖原生首屏重复猜出。权重沿用原有衰减排序，仅在完整码/合法末字前缀间共享；不扩张内部简拼。
- 分段选择累计最初编码和各段真实读音，最终上屏一致才交接；宿主两条提交入口都保留成功、允许记录、非敏感编辑框门禁，重复消费/失败不计数。
- 原生后页单独保留文字/读音/索引，覆盖分段后 `personalCandidates` 为空的情况。组合编辑、取消、重置等继续保守清理，不为保留记忆改变按键消费规则。

### 测试与审查

新增测试先复现独立召回缺失、分段码丢失；审查补充的任意 shortcut 和分段后页元数据反例也先失败再修复。宿主两入口集成验证成功/失败/禁止记录/密码框/重复回调；另测版本 3 升级和无效读音。

固定回放语料来自此前诊断的 `phrases.json` 与 `phrase-cases.tsv`，复制为 `src/test/resources/t9-personal-rehearsal.tsv`（98 个短句、266 个编码）。本轮回放提供已确认的读音、三次学习并重开数据库，在空原生候选和空补充词典下检查独立首选与次数不变；**不是新 APK 的原生解码预演，不可直接把前次 147/266 与本次结果当作同条件性能对照**。

只读审查已复查两项重要修正。后页测试仍是元数据接线单测，非真实 Rime 分段翻页验收。
