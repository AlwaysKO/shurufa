# 微信草稿变化重复截图修复计划

**目标：** 按用户提供的荣耀 X80 诊断，补齐微信单行输入栏“发送”状态的视觉边界，使正文不变时草稿与光标变化不新增截图记录。

**设计：** 保留共用 `WindowMediaCapturer` 的先裁输入栏、再计算正文精确摘要及编码的顺序。仅扩展 `WechatInputBar.kt`：完整底部边界、连续两侧背景与左侧语音图标仍须成立，右侧可为原有加号，或位置/尺寸合理的绿色发送按钮、文字前景及旁边表情图标。不靠延长间隔、固定比例裁剪或整图相似度过滤。未知、多行或证据不完整的布局仍保留截图。

**技术：** Kotlin、Android Bitmap、JUnit/Robolectric 原生图形测试。

## 实施与验证

1. 在 `WechatInputBarTest.kt` 加入明暗主题、不同密度的发送状态、草稿/光标变化、加号与发送切换回归，以及绿色消息气泡、缺图标、缺文字等负例。先运行 `:yuyansdk:testOfflineDebugUnitTest --tests '*WechatInputBarTest'`，确认新正例因输入栏未裁剪失败。
2. 最小扩展输入栏识别。通过真实媒体裁剪与 `ScreenshotContentInput` 验证正文摘要及资源稳定，正文末行一个像素变化仍改变摘要；键盘显隐造成不同可见正文仍可区分。
3. 执行采集媒体、截图更新策略、首次进入防抖、语音及入库等相关回归，独立审查新增逻辑，运行 `git diff --check`。
4. 使用本机已有 `.runtime/macos/build-apk.command` 构建 `:app:packageOfflineDebug`，核验 APK 版本、原证书、非 testOnly 与交付副本 SHA256。本机为 macOS，Windows 固定目录不可用，明确报告并保留本地 `apk/` 成品。

## 范围

沿用当前分支；不自动提交、推送、部署、安装或操作手机。用合成夹具做可提交回归，不提交真实聊天图。首次进入、新消息、语音转文字的原有触发策略保持；测试通过不代表荣耀 X80 真机已验收，也不承诺动画、多行输入等所有重复场景已解决。
