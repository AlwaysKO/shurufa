# 九宫格完整组合显示修复

## 2026-09-14 用户截图纠正

用户不是说候选数组空，而是已经输入整段字符，选字之前拼音行只显示 wo'bu'zai；选中“我不在”后才看到 pang'guang。上轮排序修复没有解决这个问题。现确认至少要在选字之前展示完整组合；是否同时要求冷启动整句汉字候选已另行询问，不能把它当成只改显示就已完成。

依据：RimeEngine用过滤后首词读音生成showComposition（其尾部包含未消费数字）；DecodingInfo显示函数把数字删除。这把“没有完整可信候选”错误地变成“隐藏用户已输入的后半段”。原生未过滤候选通常仍提供完整按键对齐的读音。

## 最小设计

- 原showComposition继续供原始提交/回车门禁使用，不改真实按键、分段、候选资格、排序、学习。
- 增加只读显示路径：已有首选完整读音优先（保持个人选择的同码读音），否则从当前原生候选元数据选择按键对齐且覆盖更长的读音，仅用于拼音显示。原生汉字被过滤不代表不能使用其拼音解释按键，不将其汉字偷偷重新放进候选。
- 真正没有读音的剩余输入也不静默删除：以键帽字母组标明尚未确定的按键，不显示数字，不编造词语，不恢复“待选拼音”文案。显示字符串绝不进入提交/学习。
- 拼音行超过宽度时允许横向查看，不缩小用户字号、不通过末尾省略号隐藏尾部。

## TDD 与验收

1. 在真实DecodingInfo→Kernel→RimeEngine显示调用链注入录制原生元数据及KeyRecordStack，先证明完整码、末字首字母仍只显示前缀；断言原始提交缓存、回车门禁、候选索引未被显示路径修改。
2. 修改T9Spelling显示辅助、RimeEngine只读getter、Kernel转发、DecodingInfo显示调用。不缓存另一套可失步的组合状态；锁定/分段路径回退现有带汉字的组合。
3. CandidatesBar加横向滚动容器，保留字体和行高；先红测长拼音没有省略、可以滚到尾部。
4. 回归我饿了、你赢了、真的吗、玩漂流、明天去爬山及充电宝/怎么/你发货吧/用得上，16步录制组合与305组候选不回归、分段学习仍通过。
5. 打包及签名校验，尽可能在设备独立目录加载同APK读出显示结果；不安装、不读取用户历史、不操作聊天。不把辅助函数或渲染自动测试称为真实触摸验收。

## 执行结果

上述显示修复已实现，未改变候选/提交/学习路径。21套件121项测试通过；305组候选回放全部字段与上轮相同；29组手机隔离快照证明选择前即可显示完整按键对应拼音。普通候选栏支持横向查看长拼音，字号和行高保留。

已生成并验证 `.17` APK，未自动安装或提交。真实触摸验收和未知整句汉字首次召回不在本次通过声明内。根因、红绿过程、复测范围、APK哈希和证据限制见 `artifacts/diagnostics/2026-09-14-t9-full-preedit/README.md`。

## 后续用户对照与取代范围

用户安装后用搜狗截图确认：仅完整拼音显示不够，必须提供完整汉字候选并一次选中；随后接受完整句子可能偶尔用词不准确的取舍。后续候选规则修复见 `2026-09-14-t9-whole-sentence.md`。本计划的显示改动保留，但不再把“整句候选尚未开放”当成当前最终产品目标。
