# 通话录音与授权上传实现计划（基础链路实施，自动录音待验证）

> **For Claude：** 必需子技能：使用 superpowers:executing-plans 来逐任务实现此计划。

**目标：** 为普通电话及微信语音/视频通话提供可验证的音频记录与上传管理；不承诺普通输入法具备系统级双向通话录音能力。

**架构：** 手机端独立管理授权、录音会话与持久化待上传队列；后端鉴权保存音频与元数据，后台提供设备隔离的查询、播放和删除。录音、哈希和上传不进入输入法按键/候选计算链路。

**技术栈：** 现有 Android Kotlin、Node.js/Express/TypeScript、PostgreSQL、Vue 3；音频能力仅使用系统允许的公开接口。

## **状态：** 2026-09-30，实施中，未完成、未打包、未进行通话测试。用户已确认一次设置授权、后续自动运行并保留必要可见提示，录音仅上传线上；线上保留及清理策略由用户管理，不作为本次实施阻塞项。

### 本轮确认（2026-09-30）

- 来源：用户要求“第一次安装新版 app 后，设置里同意一次即可”，并对“日常无需操作，但录音时保留系统必要的通知和麦克风指示”回复“可以”。
- 目标为首次设置后，在系统支持、授权有效且参与者已同意的范围内自动开始、结束、上传及清理；不以每次手动开始/停止作为最终交付方案。
- 保留系统必要通知、麦克风指示和撤回入口；首次授权不替代参与者同意，不绕过后台启动、撤权或强行停止限制。
- 自动化或双方音频能力不支持时明确报告受限，不以常驻环境录音、静音文件或隐式手动降级冒充完成。此确认不是对应平台真机能力验收。

- 清理范围：用户随后明确“上传成功后清除本地文件即可，线上后台不用你管”。本次不新增线上定时删除、备份保留或账户删除联动策略，不执行线上数据清理；线上策略由用户管理。保留原计划的上传接口、查询播放和显式删除能力，不将本条解释为取消后台功能。

## 2. 技术可行性与路线选择

不后台反复重启、抢占麦克风。

### 关键事实

普通应用并发录音可能获得静音；完整电话上/下行音频涉及系统特权能力，拥有麦克风权限不代表能获取双方声音。[Android 音频输入共享文档](https://developer.android.com/media/platform/sharing-audio-input)

麦克风前台服务受权限及后台启动条件限制，不能承诺锁屏、进程被杀后或任意后台场景都能自动录音。[Android 前台服务类型文档](https://developer.android.com/develop/background-work/services/fgs/service-types)

**阻断条件：** 若用户真机确认只能录到静音、单方声音或影响正常通话，则不得宣称完整通话录音可用。暂停该平台的自动录音实施，报告能力缺口，另行选择受支持方案。

## 3. 手机端交互与数据流程

1. 进入“通话录音”设置，查看能力说明和目的地，分别同意录音与上传；可随时撤回。
2. 在权限与参与者同意条件满足时开始本次录音；不在空闲时常驻监听环境声音。
3. 生成持久化待上传任务；低信号、系统静音、录音中断等均保留真实状态，不能仅凭文件存在认定成功。
4. 在授权仍有效且输入空闲时上传，失败退避重试；不丢弃失败文件冒充完成。
5. 收到与本次记录 ID、文件大小和 SHA256 一致的持久保存回执后，删除本应用对应文件。
6. 删除失败保留“已保存、待本地清理”状态，下次只重试清理，不能重复制造后台记录。

状态分别记录：录音状态（未开始/进行中/已结束/中断/受限）、音频质量（未验证/静音疑似/用户确认）、上传状态（待传/上传中/已保存/失败/已暂停）、清理状态（保留/待删除/已删除）。互不替代。

## 4. 元数据与存储契约

拟定记录字段：

- `record_id`：客户端生成的幂等 ID；服务端按账户、设备与此 ID 唯一约束。
- `platform`、`call_type`：普通电话/微信，语音/视频（仅声音）。
- `counterpart_display`、`counterpart_source`：可空，注明用户填写或可信来源；不猜联系人身份。
- `call_started_at`、`call_ended_at`、`call_duration_ms`：可空，注明是否估算。
- `recording_started_at`、`recording_ended_at`、`audio_duration_ms`：与通话时间分开。
- `recording_status`、`quality_status`、`failure_reason`：准确呈现受限与未验证状态。
- `mime_type`、`byte_size`、`sha256`、`stored_at`：音频校验与持久保存凭证。
- 授权版本与上传目的地标识：用于核对本次任务的适用授权，不保存不必要的聊天内容。

音频放应用私有目录及服务端非公开存储，不进入 Git，不在日志中输出录音、令牌或完整敏感身份。传输使用 HTTPS，服务端实施账户/设备隔离与存储加密，播放与下载均鉴权，不生成永久公开链接。

首版建议单文件最长 2 小时、最大 64 MiB，并设置待传总量上限；达到上限停止新增录音并提示，不偷偷删未上传文件。具体上限为建议，待产品确认。

服务端必须先完成音频校验、持久保存与元数据提交，再返回可清理回执。保存开关关闭、HTTP 请求已接收、异步处理中或校验不符均不算保存成功。网络超时后允许查询原记录回执，避免重复上传和重复记录。

上传目标已确认仅线上；不沿用其他采集的多目标同步。仅在已授权线上目标返回与记录 ID、文件大小和 SHA256 一致的持久保存回执后，才清理对应的应用自有文件；本地后台不可作为录音上传或故障回退目标。

按本轮修订，线上保留、备份及清理策略由用户管理，本次不设置自动过期、不执行线上数据清理；设置中如实说明由服务器管理员管理，不承诺固定保留期限。仅在持久保存回执验证成功后自动清理手机自有文件。本条取代此前“线上保留期限必须先确认”的实施门禁。

## 5. 后台“通话记录”页面

- 新增源码管理的菜单和路由，不依赖浏览器本地配置。
- 设备、平台、状态过滤；日期仅按日选择，提供今天、昨天、近 7 天、近 30 天。
- 列表显示通话对象、起止时间、通话时长、录音时长、录音质量和上传状态。
- 详情支持鉴权播放与显式删除；无有效音频时解释原因，不显示虚假的可播放状态。
- 未验证的双方声音明确标注，不能把“上传成功”显示成“完整录音成功”。
- 删除操作同时管理音频和记录，失败可重试；其他设备不能查询、播放或删除本设备数据。
