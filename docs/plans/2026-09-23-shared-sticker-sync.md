# 公共关键词推荐图库与 Git 同步

**目标：** 后台所有设备使用同一份关键词、匹配说法、图片顺序和原始推荐图；提交、推送后现有 main 自动部署服务恢复这些数据，新克隆也可恢复。

**已确认：** 用户指定所有设备共享。2026-09-23 本地“来砍我”含一个 GIF，匹配说法为“来砍我、来砍我啊”。图片已在工作目录，缺少数据库元数据和部署归档支持。

**方案：** 保留现有图库表和移动端协议，新图库设置使用固定公共归属，历史图片/配置保留以兼容旧版回退，新版图片查询覆盖全库，合成素材及聊天仍使用原有设备归属。版本化 JSON 清单引用 `server/uploads/stickers` 的原图，使用文件名作为可移植身份，导入时重映射数据库 ID 和排序。后台写操作自动更新清单；提交钩子收集清单及所引用的原图，推送钩子检查提交完整性。线上部署校验并复制原图后事务导入。相比整库备份，该方案不携带设备、聊天或凭据；相比对象存储，不额外依赖外部服务。

## 实施与验证

1. 公共图库：迁移历史关键词、图片、分组设置和系统图隐藏记录；修改读取、管理、下载授权及页面说明。测试一个身份上传、另一身份读取和下载，同时验证其他上传类型继续隔离。
2. 可移植清单：实现确定性导出、文件哈希校验、事务导入和排序 ID 重映射。新增清单增量导入，不删除线上独有图片；相同清单重复部署不重置在线编辑。测试空数据库恢复、重复导入、ID 冲突、缺图/坏图拒绝导入。
3. Git 和部署：保存后生成清单，提交自动收集图库数据，推送前检查。为生产发布添加只复制清单列出的图片及导入步骤；新服务器执行迁移时自动恢复。检查脚本、模拟 Git 提交/推送，并在真实 PostgreSQL 的独立测试数据库恢复验证。
4. 本地验收“来砍我”：导出当前真实数据，重启本地服务，以两个设备身份获取手机目录、推荐及图片。后台/前端构建和相关回归测试通过后整理部署文档。

## 边界

- 当前分支直接修改，不创建分支/worktree，不自动提交或推送。
- 不把个人词库、聊天、合成素材、账号或环境变量加入数据包。
- 没有对应元数据的历史 GIF 不猜测关键词，不自动发布。
- 数据包同步新增和明确的内容更新，不以较少的本地数据删除线上独有内容。导入不覆盖使用次数。
- 后台保存后仍需正常 commit/push；钩子不会暗中创建提交。只有已提交的数据才能随 push 部署。
- 线上运行部署脚本位于仓库外，需升级该脚本后新流程才能生效。
