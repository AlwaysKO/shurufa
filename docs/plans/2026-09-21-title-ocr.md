# 聊天标题 OCR 优化实现计划

> **For Claude：** 使用 superpowers:executing-plans 分批执行；用户已确认方案，在当前分支开发，不自动提交、安装或发布。

**目标：** 只改善联系人／群名标题的中文识别与内存开销，正文不用 OCR。

**架构：** 第一批保留 ML Kit、标题选择及会话稳定器。在共享截图裁剪链路中按需复制原始顶部像素，以请求作用域的 Closeable 容器交给标题识别器；不入库、不上传、不增加全局截图缓存。缺少原始输入时暂保留旧文件解码回退（区域解码延期原因见执行记录）。等待不可取消的 OCR 原生任务结束后再释放 Bitmap。第二批在隔离实验中比较 ML Kit 与 PP-OCRv6 small/tiny，不提前改变正式引擎或 API 23。

**技术栈：** Kotlin、Android Bitmap、ML Kit Chinese、Robolectric、Windows ADB。
