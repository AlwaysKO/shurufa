# USB 本地上传门控与微信空树截图设计

## 背景与证据

2026-09-16 在荣耀 ELI-AN00（微信 `com.tencent.mm`）真机复现：无障碍服务已绑定，但微信活动窗口和事件源大多只返回边界为 `[0,0][0,0]` 的空节点，导致常规 `WeChatChatAdapter` 无法取得标题和输入框，打开群聊不会生成截图。会话列表点击事件仍会暴露形如 `17:30` 的时间文本，系统截图能力可正常取得当前微信窗口。

同时，线上后台是长期目标，本地电脑 API 只是开发期镜像。无线调试、USB 充电或本地 API 不可达时，不应反复尝试本地业务上传；线上发送不得受影响。

## 设计

常规设备继续使用无障碍树页面适配器。仅当活动树和事件源均不可用，且微信产生会话列表时间行点击或明确“发送”点击时，延迟 700ms 截取活动微信窗口。截图保留标题和聊天内容，裁掉底部输入区；键盘可见时以输入法窗口上沿为下界。空树无法可靠取得会话身份，因此使用“微信当前聊天”占位身份并设置 `identity_unavailable=true`，不伪造发送者或消息方向。资源 SHA-256、截图指纹和持久化指纹继续负责去重。

上传队列仍为线上、本地独立目标。线上目标直接发送；非线上目标必须同时满足 USB 广播中的 `connected=true`、`configured=true`，以及目标 `/health` 返回 HTTP 成功且 JSON `status=ok`，才进入设备注册、事件、报告和词库发送流程。条件不满足时保留待传状态但不发起本地业务请求。

聊天文字与截图正文继续按目标分别确认：两端都确认后立即删除手机持久队列正文；线上已确认而本地尚未确认时，从线上确认时刻起最多保留七天，期满删除本地目标和正文；线上未确认时不参与任何过期清理。运行期只认持久化的线上成功时间，不根据某个域名是否还在目标表中推断成功。固定域名旧版中已经线上确认、只剩本地目标的聊天报告，只在数据库一次性升级时恢复确认时间并从升级时刻重新计算七天。

## 验收

- 单元测试覆盖线上不受门控、本地双条件门控、健康响应格式、空树截图触发条件和常规树优先级。
- 真机打开群聊后生成 WebP，图片包含群标题和聊天可见区，不含输入框。
- 线上目标确认后从该报告的目标表移除；无线调试且只有 USB 供电时，本地目标保留且 `attempted_at=0`。
- 本地 API 只有在 USB 数据连接和健康检查同时通过后才发送。
- 两端确认立即清理；线上成功、本地失败七天后清理；线上失败即使超过七天也保留。
