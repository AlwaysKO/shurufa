# 输入回归评估、手机同步与会话批量删除

> 实施遵循 Superpowers systematic-debugging、writing-plans、test-driven-development、verification-before-completion；并行仅限互不冲突的调查/后台开发。用户要求当前分支，不建分支/worktree，不自动提交。

**目标：** 先确认“也正常”通用修复对现有输入的影响，无已知退化再实施，有影响先问用户；将已连接手机可同步的数据送达本机后台；增加聊天会话批量删除功能。

**架构：** 手机优先复用既有 USB 本机上报和词库增量同步，保留身份、记录 ID、现有主控及线上配置；后台删除在现有会话组删除路由内新增原子批量接口，前端明确当前列表选择。T9 正式实现由隔离评估结果决定。

**技术栈：** ADB、Kotlin/Gradle、Vue/TypeScript/Vitest、Express/PostgreSQL。

## 1. 手机到本地同步

- 已检测到真机但 ADB unauthorized，必须等用户在手机允许 USB 调试，不能用模拟器代替。
- 同步前已将当前本地 PostgreSQL 完整备份至 Git 忽略的 `artifacts/diagnostics/2026-09-22-macos-phone-sync/local-before.dump`。本地原有设备1、输入事件1、聊天消息0、会话0。
- 授权后核对真机型号、安装版本和默认输入法；建立该真机 `tcp:3000` 到本机 `tcp:3000` 的反向转发，验证健康接口和实际上报。
- 核对后台该设备入库数量、个人词库与手机剩余队列。必要时只读导出手机保留数据做幂等补传，真实内容仅留本机忽略目录，不输出正文或凭据。
- 已在其他电脑/线上确认后从手机移除的数据不能伪称还在手机；如果遇到此边界单独报告，补齐途径按可用授权与数据来源判断。

## 2. T9 影响门禁

- 只读当前规则、历史失败实验与现有回放；在临时路径用正式算法和真实资产建立前后对照。
- 保护可信整词、精确单音节、个人优先、锁音/分段、末字补全、原生分页索引；区分召回缺失与排序问题。
- 不以补单词“也正常”或坏词黑名单冒充通用修复，不以单个用例通过宣称其他输入完全无影响。
- 有退化/无法满足用户所要求边界则保持正式代码不变，报告具体变化后请求确认。若有足够证据可安全实施，再先红测后最小修复及相关完整回归。

## 3. 后台会话批量删除

用户已明确要求实现此功能。本设计在请求范围内复用现有删除语义，不执行真实会话删除。

**文件：** `client/src/views/ChatCapture.vue`、`client/src/api/index.ts`、`server/src/api/chatGroupDeletion.ts`，对应 `client/tests/chat-capture.test.ts` 和 `server/src/api/chatContinuity.postgres.test.ts` 或专用新测试。

- 增加复选框、全选当前列表、清空选择、删除选中；默认不选中，汇总待确认桶不可选，切换手机/App/搜索清空选择。
- 确认框展示会话数和关联消息数、不可恢复说明；同名组使用用户确认时明确的 `source_ids`，不扩大为任意未来同名来源。
- 新增 `/conversations/delete-batch`：统一App下多个普通会话ID或 `{group_name,source_ids}`，明确确认字符串 `DELETE`。限定总来源不超过1000、会话数有上限；拒绝非法、重复和重叠来源。
- 在同一事务内核对所有来源的用户、App、合并状态、同名组快照，任何不符整批回滚；再统一删除，复用现有附件引用检查和可重试文件清理队列。
- 删除沿用已有级联语义，包括会话消息和相关关系资料，共享附件保留；不改识别规则、不删除手机资料、不阻止未来新采集。
- 确认及请求返回均绑定原手机/App，避免异步切换后误操作新页；提交期间禁用冲突操作。

**验证：** 先建立失败测试，再实现。覆盖取消无请求、只删选中、同名快照变化整批不删、重复/重叠/越权/跨App拒绝、共享附件保留、切手机确认失效、删除后刷新与旧功能回归。数据库测试使用独立临时 PostgreSQL 实例，禁止对业务库跑删除测试。前后端构建并用浏览器合成数据验证。
