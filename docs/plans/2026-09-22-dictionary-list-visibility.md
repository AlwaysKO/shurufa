# 个人词库增删展示修复计划

**目标：** 添加后能找到词语，默认列表删除后不再展示；保留现有手机同步和输入排序。

**已核实原因：** 线上访问日志显示北京时间 20:38:41 添加请求校验失败、20:38:51 重试成功，随后查询成功；数据库已保存“也正常 / ye zheng chang”。20:39:14 删除请求成功，数据库已保存“肿那么赴美”的 deleted 决策。合并列表按手机来源哈希顺序展示、手工词放在末尾，刷新回首页后不可见；默认全部状态导致删除项仍显示。日志未记录第一次请求正文，不能推断具体错误拼音。

**方案：** 仅后台 entries 查询优先展示手工添加来源；页面默认启用状态，保留全部/停用/已删除查询。添加后明确提示词语并滚动至结果，删除后说明状态和手机确认边界；删除最后一页后自动回有效页。备份端权限、原始上报、管理决策、手机候选排序、增量并集规则保持现状。

**实施与验证：**
1. 服务端先加入超过一页手机词、新增手工词、多来源合并与设备隔离回归测试，确认旧代码失败，再修复 entries 排序。
2. 页面测试验证默认启用、添加切换筛选并选中、删除重查与末页回退；先失败再修复。
3. 运行个人词库前后端测试、前后端构建，浏览器验证添加/删除/刷新流程；测试写入仅使用隔离数据。
4. 核对 diff，记录结果和线上部署状态。当前 main 原地修改，不自动提交/推送，不修改线上业务数据。

## 验证结果

- 新回归先失败：手工词被挤出首页、默认全部状态、删除末页不回退；修复后通过。
- 真实隔离 PostgreSQL：个人词库 30 项全部通过，包括事务、管理权限、删除策略、增量同步；没有写线上/本地业务词库。
- 前端个人词库、备份和确认框测试：30 项全部通过。新增覆盖已删除/停用同名词重新添加时保留状态并明确先恢复再同步。
- 前后端构建成功；前端保留已有大 chunk 提醒。
- Playwright 使用合成接口数据验证添加选中、刷新首页可见、删除从默认列表消失、按已删除查询与恢复，页面无 JS 错误。
- 独立代码审查无阻断问题，提示文案建议已采纳。
- 尚未提交/推送/发布线上；线上只读查询日志与两条指定词记录。未修改 Android，不改变手机候选排序。
