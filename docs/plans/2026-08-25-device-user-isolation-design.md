# 设备用户隔离设计

## 数据身份

一台手机对应一个用户空间。Android 端已有持久化 UUID `device_id`，服务端直接使用该 UUID 作为 `user_id`，避免引入账号、登录和额外映射。所有移动 API 都必须解析设备身份：优先读取 `X-Device-Id`，注册、事件、会话、位置和聊天消息接口也可从请求体读取已有的 `id/device_id`；若头与请求体冲突则拒绝请求。

所有带 `user_id` 的表按该身份读写；`input_session` 通过 `device_id` 绑定；`device.id` 本身就是用户空间标识。表情包、常用语、补全、聊天会话/消息/媒体和关系数据不再落入固定默认用户。

## 后台数据流

`/api/v1/dashboard/devices` 返回可选手机列表，其余后台 API 强制接收 UUID 格式的 `user_id`。Vue 应用顶部加载设备列表，保存当前选择，并在所有 dashboard fetch 请求中自动附加 `user_id`。切换手机时重建当前路由视图，触发页面重新加载，确保页面间不会残留上一台手机的数据。

## 兼容与错误处理

设备注册、事件、位置等已有 `device_id` 的旧请求仍能识别身份；没有身份的移动请求返回 400，避免静默混入默认空间。后台未选择或传入非法用户返回 400。历史事件、位置和聊天消息按其已有 `device_id` 无损归位，多设备聊天会话按设备拆分；确实没有设备字段的旧共享记录保留在明确标注的“旧版共享数据（待归属）”空间，不猜测归给真实手机。升级后的新数据严格隔离。

## 测试

服务端集成测试覆盖两台设备写入后互不可见、移动身份缺失/冲突拒绝、后台按用户查询。Android 单测验证每类同步请求都发送设备头。客户端通过 TypeScript 构建验证用户选择和 API 参数拼接。
