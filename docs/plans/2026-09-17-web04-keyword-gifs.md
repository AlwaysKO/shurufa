# web04 关键词 GIF 实现计划

**目标：** 继续用户已授权流程，补齐真实后台空组「确定、没关系、恭喜」，每组四风格，目标12张。

**架构：** 原登录 Windows Chrome Dev 逐张独立对话生成4×3母图，归档原图/提示词/来源/SHA并删除确认后才能下一张。复用既有构图与GIF渲染器，追加固定web04清单及独立脚本，不改web03或旧图。相对通用渲染器重构和只补旧组，本次选择新增固定批次、优先空组，改动与风险最小。

**技术栈：** CDP、TypeScript/tsx、Sharp、Vitest、真实本地后台及PostgreSQL。

1. 复核适用AGENTS、完整CREATION-POLICY、Vault入口与GIF知识卡。已实查315组、227空组、27组有1～3张；dry-run193补录项、184已有、15排除，与当前批准清单一致。数字仅代表本轮盘点。
2. 为12项设计可辨认的表演，固定镜头/身体/道具，完整手脚，原创中国成年男。不做同义重复、不恢复用户删除项。
3. `referenceCharacterRenderer.test.ts` 先加web04固定身份/字幕/来源/规格测试并见失败；追加 `ORIGINAL_WEB04_ITEMS`。新增 `web04Script.test.ts` 先验证无脚本失败，再新增 `scripts/render-web04-framed.ts`，保留原来源/清理/审计门禁与原子发布。
4. 母图逐张归档、解码、清理对话、静态检查；统一缩小与显式脚底基线对齐，无逐格变形。失败保留标明、调提示重生成，不能放宽阈值。
5. 累积framing.json渲染并运行 `npm run expression:import-keywords`；核对批次实际12项而非只看退出码。每张核验真实后台播放及删除按钮、推荐、URL解码/SHA；隔离测试用户真实删除与重导防复活，不动真实用户删除记录。
6. 定向测试、构建、只读审查和最终记录。仅最终GIF及必要文字/代码可进入Git，其他会话改动保留。不强制添加、不推送、不打包APK；不是用户逐张观看证明。
