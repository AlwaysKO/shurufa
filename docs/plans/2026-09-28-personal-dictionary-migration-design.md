# 个人词库手动迁移与完整习惯保留设计

## 用户范围与状态

2026-09-28 用户明确：不是要求现在备份，也不是配置自动异机备份；迁移时由用户自行备份，系统设计需要支持恢复。本设计取代本轮最初提出的定时/异机备份实施范围。

本轮只核对设计并用合成数据验证原生接口，不导出真实手机/线上数据，不安装备份任务，不上传对象存储、不切换服务器。以下区分现有能力与尚未实现的补齐项；文档不是功能已上线或无损迁移已验收的声明。

## 目标与选择

推荐主后台保存完整、可迁移的个人词库状态；用户迁移时备份整个 PostgreSQL 数据库及关联文件。保留稳定的设备和数据来源身份，恢复后手机继续使用原凭据和进度。备份只保证包含已成功上传到备份时间点的数据，不保证尚在离线手机上的新学习。

不采用另外两种方案：仅从 Git 恢复无法包含个人数据；依靠手机重新上报无法补齐删除规则、未上报的原生记忆及已下载的外来记录。复制手机整个应用目录又会错误继承设备身份、队列及凭据，不作为换机方案。

不增加逐键网络或文件操作。原生解码器和 App 个人加权层分开备份，不能把原生计数伪造成 App 新点击。

## 数据归属与当前覆盖

| 数据 | 持久保存位置/设计 | 当前状态 |
|---|---|---|
| 设备身份、词库绑定、同步凭据哈希 | `device`、`dictionary_device` | 已有，必须随数据库恢复 |
| App 本机真实选词次数、权重、时间、输入码、读音 | `dictionary_entry` 中带原始设备及版本的记录 | 已有上传和恢复 |
| 当前后台手动录入词 | `dictionary_dashboard_word` | 已有；换机需额外下发增量，不能只绑定 |
| 停用/删除/恢复规则 | `dictionary_policy`，共享词库组的显式状态 | 已有；全来源候选屏蔽代码尚未上线 |
| 已下发词语/习惯、确认游标 | `dictionary_addition`、`dictionary_habit`、设备确认字段及对应序列 | 已有，恢复必须保留，不重新制造点击 |
| 从另一后台/另一设备接收的词及真实习惯 | 保持原始来源和版本的副本记录，汇入主后台恢复集合 | 未完整实现；不能假定已经包含在主后台 |
| 原生 Rime 独立学习 | 保留原生语义的版本化快照及应用回执，随主数据库备份 | 未接入正式 App/服务端；接口隔离验证见下文 |
| 内置公共词库与输入方案 | 随 APK 的版本化资源和对应许可 | 已有；不冒充个人词库备份 |

原有的删除规则高于所有恢复来源。恢复数据库不是撤销禁词的理由；只有用户明确恢复词语才撤销屏蔽。普通增量缺项不能推断删除。

## 补齐设计一：把已接收的词保留为有来源的副本

当前 `LocalInputStore.dictionaryExport()` 仅导出 `learned_input` 与 `personal_word`，没有完整导出 `dictionary_added_word`、`dictionary_added_habit` 和其他恢复层。原设计防止重复计数是正确的，但不能因此将这些数据排除在完整备份之外。

新增独立副本上报协议，不能把收到的记录改成当前手机的新学习：

- 原始标识包含来源实例/设备、稳定记录标识和来源版本；上报手机只是持有副本者。
- 自己点击的记录与收到的记录分开。相同来源、相同版本重复上传或从两台手机上传，保存一次，不相加权重，不更新真实使用时间。
- 来自其他后台的手工词仍标记为手工/同步词，不生成点击次数。服务端实例标识随数据库迁移保留；本地和线上独立实例不共用新生成的标识。
- 快照/条目先校验并事务持久化，再确认。未知来源的旧版下载记录只能标为来源不完整，不能随意推断来源或声称所有真实习惯已完整备份。
- 当前主后台的删除规则仍独立生效。副本上报只保存来源证据，不接受备份端通过普通词语同步覆盖主后台管理策略。
- 后台展示本机来源、副本来源和原生快照覆盖情况，完整性未达到时不得显示“完整可迁移”。

这部分需要新协议、数据迁移和回归测试，当前代码尚未实现。

## 补齐设计二：原生记忆独立保存、兼容恢复

不能使用此前仅导出词语/读音/count 的普通 TSV 代替完整原生学习。

候选方案使用当前定制原生库 levers 的 `backup_user_dict` / `restore_user_dict` 同步快照能力，保存 c/d/t 与词库 tick。恢复由官方合并逻辑处理 tick 和权重衰减，不承诺恢复后内部数字字符串逐字相同；验收看候选行为、学习保留、重复应用不重复加权以及删除规则不失效。

### 安全生命周期

- 只在所有原生使用者尚未打开用户库的维护阶段生成/合并，必须先确认 App 启动入口和所有原生调用的生命周期隔离，不能仅靠“键盘暂时隐藏”。
- 禁止正在打字时关闭会话、修改全局数据目录或热拷贝 LevelDB。按键路径不调用导出、压缩、网络或遍历词库。
- 恢复先验证快照长度、哈希、完整性、格式及引擎兼容标识；先保留本机有效学习，再用合并语义恢复，不以旧快照覆盖本机新习惯。
- 下载期间继续使用现有学习；未进入安全维护阶段则标为“待应用”，不能先发成功回执。失败保留原库和上一个有效快照。
- 原生库重新可用之前，App 删除策略必须已加载，避免恢复内容先短暂绕过禁词。
- 必须评估大库冷启动开销；不能因为不在逐键路径就宣称没有性能影响。必要时采用用户主动“准备换机”维护入口，而不是每次唤起键盘都导出。

### 服务端保存与去重

建议以 `source_device_id + dictionary_name + revision` 保存快照，另带格式版本、引擎兼容标识、SHA256、原始大小、创建/接收时间。原生快照载荷压缩后保存在主数据库的独立快照表（BYTEA），元数据和载荷同事务提交；词库迁移不再额外依赖手机目录或散落文件。不得只存入会被替换的发布目录、临时目录或手机缓存。后台单列“原生习惯最近成功保存/应用时间”，不以 App 词条上传时间冒充原生备份时间。

同一来源版本重复接收只保存一次；手机持久保存每来源已应用版本/SHA 和可恢复的应用日志。不得在本机发生新学习后重放已应用的旧快照：官方合并会将 tick 归一，重复合并可能再次抬高旧词权重。暂存副本、校验、切换、标记成功需要崩溃恢复协议；失败或进程中止后应恢复到完整旧/新状态，不能出现“数据已合入却丢失去重记录”。不兼容快照明确拒绝，不悄悄当成空词库。新手机仅能接收已绑定个人词库的来源快照。删除规则随绑定独立恢复，不能用快照中的旧学习撤销新规则。

此设计需要正式桥接、生命周期控制、传输/存储和设备回执，均不能把当前隔离实验当作已经实现。

## 用户以后手动迁移时的约定

### 同域名换服务器

1. 迁移前让需要保留的手机同步完成，核对每层数据的接收状态。暂时停止旧服务写入，手机未成功发送的数据保留待传，防止备份完成后旧机继续收写产生分叉。
2. 用户备份完整 PostgreSQL（表结构、数据、序列、`deployment_migration` 历史），并迁移全项目需要保留的 `shared/uploads`；按本设计原生词库快照已包含在数据库内。备份运行配置与密钥属于独立私有配置，不提交 Git。
3. 新服务器恢复到空数据库，保留设备 UUID、词库组、token 哈希、数据来源身份、原始时间、序列及回执；执行仅新增的兼容迁移。不能重建身份、重算使用次数或清空管理策略。
4. 核对数据与应用后再切换域名解析/代理。旧节点在过渡期不得继续独立收写，可以代理到新服务或明确返回暂不可用，让手机重试。
5. 验证手机继续注册/同步、无重复次数、禁词继续生效；无需换设备号、卸载或清空手机数据。

### 同时换域名

在上述基础上迁移地址发现配置。`runtime_setting.collector_base_url` 的恢复值不得仍指向废弃地址；旧地址需在过渡期能通知/转发到新地址。不能在旧地址已经失效后承诺现有 APK 自动发现新域名。

### 换手机

新手机建立新身份；在主后台绑定原个人词库以继承策略，随后同步全部手工词、App 来源/副本习惯及原生快照。原手机身份和学习仍保留，不把它的数据清空来迁移。网络接收和应用成功分别确认，原生恢复未完成时不得显示全部习惯已恢复。

新手机已使用一段时间的情况必须做合并，而不是用旧手机数据覆盖新手机数据。

## 验收矩阵与界限

设计落地前需补齐下列验证，不能只凭数据库行数宣布无损：

- 服务端完整快照恢复到隔离新库：身份、绑定、词/读音、来源、次数、时间、删除规则、游标/序列及原生载荷哈希一致。
- 同域名新服务器接管：原手机凭据继续有效，旧游标能重放且不重复计数，迁移窗口无双写丢失。
- 新手机：绑定后被禁词不出现，手工词可用，原来常用词优先；新手机已有学习也保留。
- 外来副本经手机上传主后台后，只备份主库也能恢复；不再依赖原本地后台在线。
- 相同源快照/副本连续应用两次，结果不重复加权；恢复失败/断网/坏文件不毁坏旧状态。
- 原生模拟器验证之后还需真实历史库、多音字、分段、撤销学习、大库及真机性能验证。任何未覆盖范围都不称完整迁移已验收。

本轮不创建自动备份计划、不要求对象存储地址，也不操作实际业务数据备份。用户自行备份的前提不取消上述持久化和恢复正确性要求。

## 原生接口的本轮隔离证据（非正式接入）

复用当前 arm64 `libyuyanime.so`，只在自建模拟器目录使用合成学习记录；先停写再复制源库，所有 API 对副本操作。`backup_user_dict` 快照实际包含“主峰” c=1/d=1/t=1 与“朱逢博” c=1/d=1/t=2，恢复空新库后前者按官方逻辑归一为 c=1/d=0.995012/t=2；重复恢复结果相同，重启后主峰仍优先。源库文件 SHA256 未改变。

这支持选用原生学习快照，不能延伸为 App 生命周期、真实大库及手机性能已经验收。不得使用上游完整 RimeApi 表偏移调用当前定制库；其 ABI 已验证不兼容，正式桥接需按真实导出符号及能力/库哈希校验。

补测结果：新手机已有“珠峰” c=3，迁入旧库后仍保留 c=3；但旧快照的“朱逢博” c=-1 与新机 c=1 合并后仍为 c=1。原生负计数不是可靠的跨设备禁词规则，所以 `dictionary_policy` 必须独立恢复并高于全部原生结果。重复同快照的幂等只验证了期间没有新学习的情况，不能将它误称为任何时点重放都无影响；上述持久版本/SHA 去重是必需设计。

隔离证据：`artifacts/diagnostics/2026-09-28-daily-sentence/engine-eval/native-migration/result/summary.json` 及同目录原始快照；复现脚本位于其上级 `build-probe.sh` / `run-probe.py`。这些合成诊断仅保留本地，不提交到版本库。
