# 安装包词库无损压缩计划

**目标：** 缩小可覆盖安装的APK，保留全部离线词库、OCR、手写与业务功能。

**证据：** 10月8日旧包140,464,102字节（133.96MiB）；当前包189,452,352字节（180.68MiB）。主要增长为input_completion.t9idx由5,911,794变54,062,728字节。两份未压缩索引共83,883,376字节，实测deflate约30,879,951字节，预计减少53MB。

**选择：** 保留词库源文件与索引格式，移除app/sdk的t9idx不压缩配置；首次初始化在现有后台线程解压到noBackupFilesDir专属目录，按清单大小/SHA256核验、同步落盘、同目录原子发布后mmap；按内容摘要复用和替换，截断/损坏/中断不交付半文件。查询代码/排序不改。代价是首次准备耗时和约84MB展开文件，APK减小不代表安装后总占用降低。相比删词/联网下载损失离线能力、开启混淆引入反射风险，此方案范围小且字节可证明相同。

**实施与验证：**
1. 新增IndexAssetCacheTest：复制完整性、复用、不同摘要更新、损坏恢复、写入中断和并发，先失败后实现。
2. 两个索引load使用统一缓存；原有生成清单提供size/sha256；app/sdk启用默认压缩。验证简拼、整词、长句补全和公共词精确匹配。
3. 构建当前分支原签名offlineDebug，逐项比对APK资产、词库摘要和压缩方式，量化体积，原签名及非testOnly校验；交付Mac的apk目录。保留当前全部用户改动，不安装手机、不提交推送。

Android官方说明openFd只支持未压缩资产，压缩资产须通过open流读取：https://developer.android.com/reference/android/content/res/AssetManager#openFd(java.lang.String) 。因此不能只删除noCompress却保留原openFd读取。

## 审查边界

独立只读审查通过；实际资产与清单一致，两个入口均从Launcher后台初始化调用，原子发布、并发锁和旧文件清理范围符合设计。为检测同长度损坏，每次进程初始化仍需读取并校验约84MB缓存；不是只有首次展开才有I/O。缓存位于noBackupFilesDir，不进入系统备份。空间不足/暂时写入失败沿用已有降级及下次进程启动重试，不能宣称本轮已测真机启动耗时或低空间自动即时恢复。
