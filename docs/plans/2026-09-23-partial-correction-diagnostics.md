# 局部纠错学习与候选诊断实施计划

**目标：** 基于用户提供的线上分析，扩展明确尾部纠正的识别，保留正确前段的已有奖励，并补足真实选择时的候选证据。删除次数不当作错字率，不为个例强制调整排序。

**范围：** 当前分支开发，不提交、不部署、不安装；保留现有聊天采集相关改动。推荐图自动清空仍属另一个未解决事项，不混入本轮完成声明。

## 方案与约束

- 保持上屏2秒内开始键盘退格、首次删除后15秒内原位替换的时间窗。已有整词同码纠错继续有效。
- 仅在完整编辑快照能唯一定位、连续尾部删除、前后上下文不变、原候选逐字读音有效、替换候选与删除尾部的读音和字数一致时，认定尾部纠正。缺少读音、光标移位、异音改写、外部修改、超时均不撤销。
- 错误整句及涉及错误尾部的本笔临时奖励撤销；已实际点选且完整留在前段的分段奖励保留。不凭未选择过的子串制造点击次数，不扣历史次数，不触碰既有词条或跨设备记录。
- 临时奖励在SQLite事务内限制为原记录的子集，保留原时间与上传目标；重复更正、过期结算不能增加奖励。无需改数据库版本/同步协议。
- 候选诊断只附在既有获同意的成功上屏事件metadata中：点击前实际前5项候选、选择的绝对位置、原始输入码、候选来源/读音、APK版本；分段选择有数量上限和截断标记。失败上屏、密码和禁学习输入、关闭采集均不上传。
- 补本笔奖励ID及撤销结果元数据，后续可核对是否应用；不从历史统计反推已撤销成功。

## 实施与验证

1. `CorrectionLearningTracker.kt` / Test：测试先行，覆盖单段尾字与跨分段尾部纠正、同码整词兼容，以及正常改写/异位/歧义/超时反例。
2. `LocalInputStore.kt` / PendingLearningTest：事务保留奖励子集，测试历史不减、重复同词分段不多保留、到期/重复/重启与备份边界。
3. `OfflineT9Candidates.kt` / `ImeService.kt`：接入选择读音、实际分段、撤销结果；验证两条宿主提交入口与既有隐私门禁。
4. 独立候选诊断任务：`RimeEngine.kt`、`T9CommitTracker.kt`及测试；主任务整合到既有事件metadata，测试当前候选快照而非重查结果。
5. 只读查找线上同批设备/时间范围，拿到具体原码后回放。范围不明则记录缺口，不能把旧数据回放当作本批长串分析，也不盲改词频。
6. 运行定向Android单测、源差异检查、独立审查；构建原签名非testOnly APK并核对实际版本/签名/SHA。本机不能访问Windows E盘须明确交付缺口。

- `restrictLearning` 以事务限制原临时奖励的多重集合，避免重复同词段多保留；未知奖励、过期、重复更正、尝试新增子项均不产生新的奖励。正式历史、原有词条不减。

## 适用边界

- 29个局部或位置变化样本中仅17个符合前缀保留形状，旧日志无完整读音，不能宣称新逻辑必定覆盖17个，更不能将其视为错字率。
- 整词一次选中时，未独立选过的正确子串没有独立奖励可保留；不因此制造子串点击。跨多笔纠正后继续退格进入此前前段的情况仍保守不回溯。
- 确定替换需要既有获同意的可读完整快照；关闭采集、密码/禁学习输入、不可读快照、歧义、异音或异位不推断纠错。不上报未选中密码/敏感候选内容。
- 诊断仅随有原始学习选择证据的成功上屏事件产生，不把标点/无学习码当成候选选择。每段code仍为整串学习码；真实余码及锁音历史没有完整记录，不能仅凭code重放每段的精确引擎状态。
- 当前离线回放没有当时手机的原生数组和个人学习状态，不能用其排名声称线上当时的首选。真实误触/排序区分需升级后的诊断数据。
- 本机交付包会包含当前工作区已有的其他改动，但那些聊天采集变更不属于本任务实现/205项回归范围。未操作手机发送或自动安装、未提交或推送。
