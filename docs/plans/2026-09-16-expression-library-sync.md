# 独立合成图库与版本驱动同步 实现计划

**目标：** 15张合格无字GIF内置；后台可独立上传AI底图、SHA去重；后台关键词推荐可触发手机；每次打开键盘先查轻量版本，输入过程不查版本，版本不变不下载已缓存GIF。
**架构：** 用户作用域的版本接口GET /mobile/expressions/versions返回{version}；变更后GET /catalog返回完整、可持久化的元数据快照（complete:true），未变不拉目录。目录包含系统素材、该用户关键词推荐与独立合成底图。客户端按SHA复用字节，关键词匹配完全在完整本地索引完成；断网回退持久目录。上传文件存储与授权遵循现有用户隔离，不与关键词用途混用。
**技术栈：** Express/PostgreSQL/Vue、Kotlin/OkHttp、Vitest/JUnit/Robolectric。

## 分工与验证
1. 服务端：轻量版本/完整目录/推荐桥接；独立合成上传列表删除、并发SHA去重、验证GIF/无字确认/来源及安全区，鉴权隔离、版本不依赖读取图片。先写失败测试再实现。
2. 后台：独立AI合成页或标签，上传/预览/删除/去重反馈/无字及授权确认；关键词页剔除synthesis-template。测试和构建。
3. 素材：基于本轮明确批准新增9张（原6+新9=15），失败豆豆排除，保留旧带字素材与60退役标记，生成Android内置资源及SHA验证。
4. Android：打开键盘一次轻量检查、未变零目录/零GIF请求；完整目录持久化、版本变后仅缺失SHA下载；自动推荐和AI手动入口使用可解析本地文件；不拿网络GIF再对比。覆盖重复输入、重开进程、添加/删除/更新、断网、跨用户、并发与损坏文件。
5. 顺序跑测试/构建，不与其他会话共用构建输出。解包APK核对15个GIF并安装验证设备APK SHA；不发送联系人测试消息。

当前分支执行，按subagent-driven-development技能拆分独立模块；不创建worktree、不自动提交他人改动。用户2026-09-16明确同意打开键盘时检查版本的更新时机。素材授权沿用项目记录，未声明独立法律核验。
