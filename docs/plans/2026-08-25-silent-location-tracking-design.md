# 静默尽力型位置轨迹设计

## 目标

在不启动前台定位服务、不发送应用常驻通知的前提下，尽可能记录路线轨迹。输入法活跃时主动监听 GPS/网络定位；输入法不活跃时只通过 Android 被动定位接收其他应用触发的新位置。系统没有产生定位时允许轨迹断开。

## 上报策略

定位过滤发生在 Android 客户端，请求发出前完成：

- 定位数据年龄不得超过 1 分钟，时间使用 `Location.time`。
- 定位精度必须优于或等于 200 米。
- 两次成功上报至少间隔 1 分钟。
- 首个有效位置允许上报。
- 后续位置的球面距离必须大于 `max(50 米, 上次精度 + 本次精度)`，以排除静止时的定位漂移。
- 只有服务端返回成功，才持久化本次坐标、精度、定位时间和成功上报时间。
- 上次成功位置存入 SharedPreferences，应用重启后继续去重。

## 定位来源与生命周期

- `PASSIVE_PROVIDER` 在定位采集开启且权限可用时保持监听，用于接收百度地图、微信等其他应用触发的定位。
- `GPS_PROVIDER` 与 `NETWORK_PROVIDER` 仅在输入法开始输入后注册，在输入结束后注销。
- 输入法生命周期通过 `ImeService.onWindowShown` / `onWindowHidden` 通知 `DataCollector`，避免仅有编辑框焦点但键盘未显示时启动主动定位。
- 启动时的最后已知位置也必须经过同一新鲜度、精度、频率和距离策略，不给缓存位置特殊通道。
- 声明 `ACCESS_BACKGROUND_LOCATION`，但不使用前台服务；后台回调频率最终由 Android 和手机厂商控制。

## 并发与失败处理

GPS、网络和被动定位可能同时回调。所有“读取上次位置 → 判定 → 请求 → 成功后保存”操作由协程互斥锁串行化，避免两个相近位置并发通过过滤。HTTP 失败或异常不更新上次成功位置，后续新定位仍可重试。关闭位置采集时注销全部监听器。

## 验证

- 纯 Kotlin 单元测试覆盖新鲜度、精度、一分钟限流、自适应距离、首次位置和球面距离。
- Android 构建与现有测试全部通过。
- 当前荣耀手机授予后台定位权限后实测：输入法活跃可上报；静止一分钟以上不新增；其他应用定位可触发被动更新；数据库时间来自定位本身。
