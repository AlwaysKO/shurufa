# 输入法后台省电优化

> 同日后续要求已调整为空队列/未录音待机30分钟、位置报告5分钟，且授权真机安装；以下为首轮历史验证，最新实现和验收见 [Android Studio恢复与频率修订](2026-10-06-studio-idle-location.md)。

**目标：** 减少用户反馈的耗电，重点消除没有 Wi-Fi 时无效的截图队列扫描、批量同步与空队列轮询。

**已查证：** DataCollector 有图片待传时每秒查队列/触发同步，未在快速轮询入口判断 Wi-Fi；普通同步30秒一次、新事件5秒合并触发。CaptureUploader 和通知原图处理器无任务时仍每3秒查询队列。当前无 ADB 真机，无法确定上述工作在用户实际电量中的占比。

**实现范围：**

1. 图片快速检查只在可用 Wi-Fi、输入/游戏空闲且同意有效时进行；无 Wi-Fi 不读图片待传列表。用回归验证入口条件，保留已有图片 Wi-Fi 传输约束。
2. 新增简单、单调时钟驱动的普通后台同步节流：无 Wi-Fi 合并为最多每5分钟一次，数据仍本地持久化；已有 Wi-Fi 节奏不变。新事件按剩余时间合并调度，网络恢复时取消旧慢等待并及时补传。应用使用记录保持原采样频率，仅网络批量上报采用同样节流；“立即同步”明确绕过自动间隔，权限和游戏守卫仍生效。用时钟测试频率上限和网络切换。
3. 两处旧媒体队列改为事件唤醒及60秒空闲兜底；有进展仍1秒续传、进程恢复立即检查，保留输入和游戏避让。用虚拟时间验证等待、事件合并、取消和任务续传。
4. 保留上一轮尚未提交的录音自动发现实现。录音是否改为仅 Wi-Fi 上传已询问用户，未收到回复前不改变此权限/网络范围。普通通话记录和定位采样策略不在本轮改动范围。
5. 运行相关回归、独立审查及APK构建；Mac项目apk目录交付原签名非testOnly包，不自动提交、推送或部署后台。不得将程序触发次数减少等同于已测得电量节省比例。

补充查证：录音服务在没有录音时仍每秒执行权限和SIM查询，改为空闲60秒健康兜底；来电事件仍由系统回调立即响应，实际录音开始后重排1秒健康检查，挂断恢复空闲间隔。开始录音重新检查系统权限，销毁后不保留回调。真实Service/Handler的Robolectric回归覆盖上述边界。

实现依据：[Android 批量网络请求与电量影响](https://developer.android.google.cn/develop/connectivity/minimize-effect-regular-updates?hl=en)、[Android 网络状态回调](https://developer.android.com/develop/connectivity/network-ops/reading-network-state)。不新增主动网络探测来判断Wi-Fi，沿用系统验证状态。
