# 零 Token 表情反击链设计

日期：2026-08-25
状态：已确认，进入实现

## 1. 目标与边界

本阶段在现有聊天消息、媒体资源和关系档案之上，统计“对方发某个表情后，用户历史上通常回复哪个表情”，形成完全确定性的零 Token 表情候选。候选只引用已经采集并按 SHA-256 存储的真实发出资源，不调用视觉模型或大语言模型，不生成或修改图片。

本阶段实现服务端候选引擎、移动端协议和后台预览。Android 端尚不能可靠识别当前聊天会话，因此暂不请求或展示这些候选；真实应用适配器完成后再接入富内容提交能力。

## 2. 可用消息与资源

首版只把 `message_type` 为 `emoji` 或 `sticker`、带 `role=content` 且 `position=0` 媒体资源的消息视为表情消息。普通 `image` 可能是照片或截图，不自动纳入表情统计，避免把私人图片推荐为斗图素材。

输入表情使用精确 SHA-256 标识；感知哈希相似聚类留待后续，不在首版自动合并。候选返回资源 ID、SHA-256、MIME、尺寸和现有 `/uploads/...` URL，不复制文件到独立 `sticker` 表。

## 3. 四层候选路由

候选按以下顺序合并：

1. **表情反击匹配**：当前会话中，历史上同一 incoming 表情后紧邻的第一条 outgoing 表情；
2. **当前关系高频**：当前会话中用户最常发送的表情；
3. **关系类型高频**：其他相同 `relationship_type` 会话中的高频发出表情；`unknown` 跳过；
4. **用户通用高频**：该用户全部会话中的高频发出表情。

每层按使用次数和最近使用时间排序，跨层按候选资源 SHA-256 去重。输入 SHA-256 可为空：为空时跳过第一层，仅返回高频回退。默认返回 6 个，硬上限 20 个。

## 4. API 与后台

移动端新增：

```text
POST /api/v1/mobile/relationships/sticker-candidates
```

请求必须包含完整 `platform + account_key + external_key`，可选 `incoming_asset_sha256` 和 `limit`。未知会话仍返回 200、空候选及 `conversation_not_found`，不得模糊匹配。

后台新增：

```text
GET /api/v1/dashboard/relationships/:conversation_id/incoming-sticker-assets
GET /api/v1/dashboard/relationships/:conversation_id/sticker-candidates
```

关系记忆页面展示该会话最近出现的 incoming 表情缩略图。选择一个缩略图后预览反击候选；不选择时预览该关系的高频表情。候选显示来源、历史次数和时间。

## 5. 安全与降级

- 查询始终按 `user_id` 隔离，并验证会话归属；
- SHA-256 只接受 64 位小写十六进制；
- 资源不存在、会话不存在或没有历史样本时返回空结果；
- 只返回已有静态资源路径，不进行新文件写入；
- 不把普通图片自动当作表情，不基于 pHash 猜测相同资源；
- Android 未可靠识别关系前不消费接口，避免表情串台。

## 6. 验证

自动测试覆盖四层回退、紧邻反击配对、跨层去重、消息类型过滤、用户隔离、未知会话、非法 SHA-256、最近 incoming 表情列表和 API 稳定字段。完成后运行服务端全量测试、构建与迁移、客户端生产构建、被动性门禁和差异检查。
