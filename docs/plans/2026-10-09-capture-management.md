# 应用页面与视频停留管理实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 对齐聊天采集的筛选、单条/批量删除及旧记录清理；视频首帧不在应用页面重复采集、上报和展示。不支持手工新增采集记录、换图或修改原始观看时间。

**Architecture:** 两个后台列表继续独立，视频图片共用page_capture资源与上传回执，但应用页面列表排除media_feed及被视频引用的图片。展示名称、备注作为后台独立元信息编辑。删除使用可验证原始回执的墓碑防止重试复活，删除视频时清理不再被使用的视频帧；删除应用图片不破坏视频时长。清理先冻结预览范围，再按批次执行；切手机/筛选后废弃旧异步操作。

**Tech Stack:** TypeScript、Express、PostgreSQL、Vue、Vitest、Kotlin/Robolectric。

## 1. 服务端（独立开发）
- 修改 server/src/api/pageCaptures.ts、videoVisits.ts，增加共享管理模块和迁移。
- 扩展日期、关键词与视频状态等筛选；增加PATCH元信息、POST批量删除、cleanup/preview与cleanup/batch。
- 用隔离PostgreSQL集成测试先复现缺失行为，再验证权限隔离、重复上报、已删回执、关联帧及预览失效。

## 2. 前端（独立开发）
- 修改 client/src/views/PageCaptures.vue、VideoVisits.vue，关联api/browser与测试。
- 筛选、当前页选择/取消、单条和批量删除、保留1/7/30天清理预览、名称/备注编辑；操作过程中保护手机范围及失败反馈。
- 测试真实交互与请求载荷，执行前端构建和桌面/窄屏浏览器回归；保留首帧点击居中放大。

## 3. 手机端去重与整合
- 核验 BrowsingPageServiceBridge、LocalPageFrameReader、PageCaptureOutbox，避免普通页面链路与视频链路争抢同一首帧。
- 重用已有图片资源ID与可靠ACK，不双传同一资源。观看记录仍按每次前台停留独立记录，不合并不同次观看。
- 先写去重回归，再跑相关Android测试；检查所有组件契约与服务端构建。

## 交付范围
当前分支开发，保留用户红包等改动；不操作手机、不安装发布、不提交或推送。仅本地代码及隔离测试，用户后续自行验收。历史重复只做展示去重，不擅自删除真实历史观看段。

## 本轮实现与验证结果

- 两页已具备日期/名称备注与各自类型状态筛选、当前页选择、单条/批量确认删除、名称备注编辑；视频保持单首帧。旧记录清理一次确认后自动分批，可停止和失败续传；删空末页自动回有效页。
- 同一导航、窗口、同意和策略范围的两候选共享一张安全分类帧，最多短暂复用1.5秒；切导航清空，后台图片时间保持原始取帧时间。图片入队/可靠ACK去重继续复用已有资源ID，不合并不同次停留。
- 应用列表排除信息流及视频引用图；删除保留无图墓碑用于校验重试，晚到新访问可保留时长并显示缺图。清理预览冻结ID与元信息签名，批次失败回滚不推进游标。
- 本机实跑通过：Android相关306项；服务端专用PostgreSQL33项；前端全量470项；服务端/前端构建及三份本地浏览器回归通过。截图测试用虚构接口，不代表真机或线上验收。
- 测试证据：`.runtime/capture-manage-20261009/`；隔离数据库已停止，目录和日志保留，未操作业务数据库。
