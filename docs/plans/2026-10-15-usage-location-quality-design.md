# 手机使用时间、定位质量与地图交互设计

## 授权与状态

- 来源：2026-10-15 当前对话。用户选择以“最近使用到什么时候”为主，不再把不完整的交互采集称为最后实际操作；速度/高度不推断出行方式，接受明确标注的区间估算速度。
- 用户要求提高有效速度、高度比例，而不只是修改“未知”文案；拿放、摔落不应成为出行轨迹。用户在了解固定 50 米过滤与地图定位的区别后确认“继续”。
- 本设计采用先优化原生定位、再评估是否需要第三方 SDK 的方向。本轮不接百度 SDK，不新增第三方数据共享，不授权部署、安装、提交或推送。
- 本轮代码实现、分任务双审、跨端最终审查与必要验证已完成；全量既有失败单列，未冒充全绿。新原签名包20261015.17已交付E盘，未安装或部署，真机精度/熄屏效果/续航待验收。上一轮熄屏定位与五分钟批次的未提交修改保留。原APK20261015.13不包含本设计的新修改；完整证据及交付路径见实现计划最终记录。

## 已知证据与未确定事项

1. `LocationUploadPolicy` 按 `max(50m, 两点水平精度之和)` 判断入队位移，成功保存后 60 秒内的新点被拒绝。
2. `LocationJumpFilter` 和 `BalancedLocationPolicy` 另有 50 米运动判断，不能仅改入队常量便声称支持短距离步行。
3. `BalancedLocationService` 已请求 GPS/network/passive。`DataCollector.persistLocation` 接到回调直接尝试落盘，存在网络点先保存、稍后 GPS 点因间隔被挡的代码路径；尚需失败测试证明具体顺序，不声称这就是用户历史轨迹缺失的唯一根因。
4. 速度缺精度就不作为可信速度；高度缺垂直精度或误差大于 20 米便不保存正式高度，且当前 context 没有原始高度和垂直精度诊断字段。历史未保存的数据不能恢复。
5. `UsageSessionEngine.close` 可取 `pausedAt` 作为使用段结束，故 `endReason=off` 不足以还原原始熄屏时间。原始 UsageEvents 已进入 query，可复用，不需新增高频采样。
6. 地图中间点半径仅 5px；路线分析已按设备及 `occurred_at` 排序，但起终点标记另依赖列表反转。重叠点缺乏明确选择入口。
7. 用户提供的是线上分析报告，本轮未独立读取生产数据或操作手机。来源占比、GPS 是否实际返回、真实耗电仍未测量。

## 一、时间语义与数据流

- 主区名称为“最近使用记录”，按已收到的应用活动与熄屏/锁屏事件的实际发生时间展示，并同时标明是哪种证据；不声称是最后触摸或当前在线。最近应用活动、熄屏、锁屏分别保存，已有交互证据保留为补充。
- 从已授权 usage 查询窗口提取 resume/pause/off/lock 原始时间；采样游标、采样时刻、服务器接收时刻、自动任务不能生成新的使用证据。停在前台不按当前时钟延长最后活动时间。
- 继续保持原使用时长计算，不为时间展示改变 pausedAt/短段/桌面过滤语义。即使使用段被正常过滤，合法的原始屏幕边界仍可作为独立证据。
- 本地保存有限的最新分类快照，按目标记录未确认版本。随应用使用批次携带；无使用段但有快照时允许小型快照批次。无任何新数据不上传，继续两网五分钟及系统恢复规则。
- 服务端严格验证可选字段，按类别单调更新，乱序不倒退；合法使用段与快照在事务内处理。确认精确到快照版本，旧批次响应不能确认后来产生的新快照。关闭保存、撤权与目标切换沿用现有保护，不伪造保存成功。
- 发生时间与接收时间分别保留。只说明“最近收到的记录”及已知本批到达延迟，服务器不能在看不到手机队列时编造“待上传数”或宣称已全部同步。
- 老客户端缺新字段正常接收；历史交互继续展示原语义；不能把旧 off 使用段 end_ms 回填为原始熄屏时刻。需要历史显示时，仅可明确标为“应用使用段结束”，不得冒充新增原始事件。

## 二、位置质量与短距离变化

- 保留非 Wi-Fi 每分钟采样目标、Wi-Fi 稳定降频、每五分钟网络合批，不将本轮变为常驻高频导航。
- 先用确定性测试验证多来源到达顺序。采用有界的短时择优窗口，在同一采样机会内优先新鲜、精度更好的合法点；窗口不能因连续回调无限后移，停止/撤权必须取消，失败不得推进保存基准。
- 如果实际复现表明无需新窗口便可解决，则选择更小的修复。不能用无期限等待 GPS 导致网络可用点永久丢失，也不能改写已经远端确认的历史坐标。
- 用共享的精度感知判断替代高质量点上的固定 50 米下限；粗糙网络定位仍保守。实现候选是高质量点采用 `max(10m, 两点精度之和)` 并结合连续移动证据，具体常量须经步行/静止回归，不是保证 10 米必定上报的产品承诺。
- 短距确认、固定静止锚点、乱序/重复/跳点、GPS/network 交替必须一起验证。不能把同一回调重放当两次独立确认，不能靠当前或上一个高速值放行不合理跳点。
- 拿放、摔落没有持续的可信地理位移时不新增轨迹，不接入加速度积分、跌落检测或地面高度推算。此处测试模拟的是定位抖动/异常速度，不冒充真实摔机验收。

## 三、速度和高度

- 可信系统实测速度优先，统一 km/h。缺精度的原始速度可保留诊断，但不提升为可信，不按步行/骑车预设数值或裁剪高速度。
- 区间估算在前端基于同设备、时间连续、精度合格且位移明显超过误差的点进行；只作为显示推导，不改原始报告或服务器历史 speed。
- 标注“区间估算”和起止时间，不冒充瞬时速度或真实沿路行驶里程。重复时间、逆序、跨设备、断档、异常跳点、位移淹没在误差中均不估算；停车时保留可信 0，不用区间均值覆盖它。
- 高度保留有限原始数值、垂直精度、类型与拒绝原因。可信值和仅供参考值分层展示；WGS84 椭球高不叫海拔或离地高度，无可信转换就不改标注。系统根本没有提供高度时仍未知，不从经纬度或速度编造。
- 服务端 context 是严格白名单，必须先补兼容校验和测试；旧 payload 继续有效。后台未部署前，新字段不能直接导致整条位置被拒收，交付需明确服务端升级顺序或采用明确能力门禁。

## 四、地图交互

- 保持真实坐标，扩大鼠标/触屏命中区域，而不是把点挪开冒充真实位置。
- 点击近邻/重叠点提供按时间排列的记录选择，选中高亮并与详情对应；弹窗不被自动刷新无故关闭，缩放/中心保留。
- 所有连线、起终点和方向标记使用同一份按设备/定位发生时间稳定排序的数据；相同时间采用稳定 ID 决胜，不按上传时间排序。
- 不跨设备、长时间断档或异常跳点强连。明确线段是定位点连接，不是道路导航还原；保持已有跨日分段语义。
- 不新增地图服务商或改变坐标系，保留 HTML 转义、移动端布局和事件清理。
