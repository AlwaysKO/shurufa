# 九宫格全词库与短句预演计划

目标：先测量现有规则，不修改应用规则；按实际覆盖结果提出待确认的新规则。
架构：复用已安装 APK 的隔离 app_process 测试。枚举主词库和领域词库的完整码，按同码聚合所有目标；另加词库外短句及输入路径边界。不得把同码多个词均要求第一，也不得把词库收录当语义正确标签。
技术栈：已有 Java 设备诊断程序、Python 语料生成/汇总、既有 Kotlin 回归。

## 步骤
1. 固定 APK 哈希，读取目标目录规则；保留其他会话改动。
2. 在 artifacts/diagnostics/2026-09-14-t9-rehearsal 中生成可复现有限语料，核对词条/同码数量与目标拼音来源。
3. 扩展诊断测试为逐码输出 JSONL，先跑小批校验与计时，再全量运行；失败/中断不得计为通过。
4. 汇总原始/后处理目标召回、首选/前五命中、正确原生候选被删、原生缺失但本地补回；词库外正常短句独立统计。
5. 已知坏候选、末音节补全、退格重输、后页、学习/分段边界单独报告，不拿完整码词库遍历冒充全部交互覆盖。
6. 根据结果更新审计结论和规则草案，注明未决项；不装新 APK、不清空个人记录，不声明穷举所有自然语言组合或零回归。

## 判据
- 完整码：统计目标是否存在以及名次，不对所有同音词强制第一。
- 语义：正常短句和已知不合理组合为独立标注组，其他原生新串只作待审项。
- 覆盖：只有完成记录且总数核对一致才算该有限集合遍历完毕。
- 真机隔离与实际聊天界面/真实个人历史验收分开。

## 用户追加想法：跨输入法迁移（待来源确认）

用户希望换输入法时导入旧输入法的个人词库与习惯，避免重新学习。当前仅作可行性讨论，不代表已授权读取私人输入记录或实施导入。

- 优先检查旧输入法主动导出的用户词库/短语文件；系统 UserDictionary 仅是另一种可能来源，不等于旧输入法全部记忆。
- Android 应用私有目录默认隔离；不能把安装权限或 USB 连接当成读取其他应用私有库的授权与能力。
- 若能导出，先核对词语、读音、频次、时间戳、编码及数据格式；不同引擎的权重不直接等价。
- 后续设计应区分导入来源证据与本机真实选择次数，支持预览、去重、合并、失败回滚与再次备份，不静默上传或覆盖现有记录。
- 具体来源输入法尚待用户回答。迁移不能替代本轮召回/过滤/分段学习缺陷的修复，否则导入后仍可能找不到词。
