# 对方输入状态采集过滤

用户要求：会话标题只要以“对方正在输入”开头，任意尾缀均不上报，包括 `对方正在输入`、`对方正在输入.`、`对方正在输入..8`。

方案：复用统一标题状态规则，对标题做既有 Unicode/空白规范化后匹配前缀。有页面树时在物理截图前跳过；OCR 后即使沿用已确认联系人，也按本帧 observedTitle 拦截入队。首帧输入状态不得借后续正常标题重新上报；确认补拍输入状态不得改写正常首帧。通知补偿使用相同规则。正文出现这句话不作为标题过滤依据。

步骤与验证：
1. 添加前缀噪声、身份连续性、首次输入状态、确认补拍、入队和通知补偿回归，先验证失败。
2. 最小修改匹配、截图持久化与公共采集入口；保留标题恢复后的采集资格，不标记被拒绝帧已保存。
3. 扩大执行相关采集回归，独立审查、diff 检查，再按原签名构建本地 APK。

保留上轮输入栏修复，当前分支开发；不删除既有线上记录，不部署、不操作手机、不自动提交代码。真机效果单独验收，Windows E 盘交付缺口沿用本机说明。

## 验证进展

- 核心回归先出现6项预期失败，修复后59项通过；通知入口及输入状态恢复资格的2项回归先失败后修复。
- 审查发现并修复通知空树降级绕过已知输入标题、旧宽标题区域可能读到正文两处遗漏。实际服务/媒体链路测试先验证缺少精确标题输入失败，再通过；补充真实协调器入队计数断言。
- 最终39个测试类、270项回归通过，无失败、错误或跳过。日志及计数位于 `.runtime/peer-typing-filter/`。保留既有Android弃用及解码器诊断输出，未当作业务失败。
