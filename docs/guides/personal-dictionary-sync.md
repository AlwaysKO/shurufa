# 个人词库与换机同步

## 使用顺序

1. 后台先通过正常发布流程依次应用 `016_personal_dictionary.sql`、`017_dictionary_target_role.sql` 并部署相应 server/client。2026-09-16 本地已应用这两项迁移，不代表线上已部署。
2. 旧手机**覆盖升级**支持本功能的 APK，不卸载、不清数据；开启已有「个人数据同步」开关并联网，先让旧记忆完成备份。
3. 新手机安装新版、启用输入法并允许个人数据同步。首次初始化会尝试读取系统公开词典，受权限及手机实现限制；不会读取搜狗等私有学习库。
4. 登录主控后台，在顶部设备目录选择旧手机，打开「个人资产 → 个人词库与换机」。默认仍以线上为主控；本地电脑接收独立备份，可切换设备查看新旧手机上报，但不下发管理决策。
5. 查看新旧手机的型号、设备编号、最近上报时间。选择新手机的「绑定到当前个人词库」。如果该手机已绑定其他手机，确认框会说明整组合并；先确认设备属于同一人。
6. 使用「各手机原始上报」查看来源明细，或「按词合并查看」去重查看词语。可按手机、词语、拼音、状态筛选，分页和批量保留/停用/删除。
7. 后台显示「等待手机同步」时还没有生效确认；手机联网且后台任务获准运行后恢复，确认版本后显示「手机已确认应用」。Android 省电策略或关闭同步可延迟执行，不能承诺实时推送。

## 数据含义

- 实际选词记录：输入码、次数、衰减权重与最后使用时间。
- 词条读音：文本、已知拼音及来源。系统导入不伪造选词次数，未知读音显示「未记录」。
- 同一词有多设备/编码记录是正常来源明细，不代表重复点击。恢复层不再次上报为本机来源，重复传输不叠加次数。
- 停用/删除按词作用于此共享个人词库的所有读音和编码。原始上报保留可查，决策标记防止重导入复活；明确恢复才重新启用。
- 旧版本的删除只管理 App 个人补充层，同名原生词仍可能显示。2026-09-28 本地实现增加全来源候选屏蔽，需要部署 `031_dictionary_candidate_policy.sql` 及新版后台、手机覆盖升级支持该能力的 APK；以设备能力和同步确认判断，不因后台有删除记录就假定旧手机已屏蔽。此功能仍不迁移其他输入法私有模型或 Rime 模型文件。
- 词库向线上与当前配置的电脑地址独立上报，各自保存凭据、上传进度和重试状态；旧版线上凭据保留。只从主控后台恢复和确认，另一端显示「仅备份」，禁用绑定/保留/停用/删除，避免让用户误以为操作已下发。主控离线时不自动改用备份端决策。
- 导出个人数据经过敏感文本过滤，但不能声称能识别所有未标注敏感内容。原有个人数据同步同意开关继续生效。

## 本地看不到上报时

先区分设备注册/输入事件与个人词库：设备在线不代表词库已收到。电脑地址使用手机侧 `127.0.0.1:3000` 时，需要项目既有 Windows→WSL relay 与 ADB reverse；重启 WSL 或重新连接 USB 后检查该通道。局域网直连则检查地址可达性。

本地 API 必须完成两项词库迁移。手机须覆盖安装包含双端词库上报修正的 APK；此前仅线上同步的版本不会因本地服务修好就开始传词库。不要卸载或清数据来排查，否则可能丢失未备份的学习记录。

## 换机注意

新版用不参加备份的设备锚点区分手机，首次升级仍保留老设备编号。系统备份排除本机来源学习库、待传队列、同步凭据和旧迁移状态，防止新设备重复计数或跳过公开词典检测。其他键盘设置仍遵循系统备份。

因此应先升级旧手机并确认上报成功，再更换手机。未上传数据、旧版本生成的系统备份、忽略 Android 排除规则的第三方克隆工具，不保证恢复。不要以直接复制 `local_input.db` 或设备偏好替代此同步流程。

本功能尚无解除绑定或撤回已离线下载数据的管理入口；绑定前核对设备。复制设备编号不能替代同步凭据；初次凭据采用首次注册绑定，不代表硬件可信认证。

## 2026-09-22：手工录词与一键增量同步（取代上方备份端不得下发的旧范围）

当前代码增加了独立的纯加法通道。本地和线上后台均可新增词语、增量发送到选定手机；备份端仍不下发停用、删除或绑定管理决策。此条不等于任意线上实例已升级。

1. 后台应用 `023_dictionary_additions.sql` 和 `025_dictionary_habits.sql`，部署相应后端/前端；手机覆盖安装支持习惯接收的新 APK，保留数据。
2. 在“个人词库与换机同步”输入词语和逐字拼音，例如“买菜 / mai cai”。手工词没有伪造选词次数。
3. 勾选接收手机。点“一键同步全部习惯和词语”时，发送当前个人词库全部启用且有效的已保存记录，包括真实输入码、次数、权重、最近使用和有依据的拼音/手工词；不受表格筛选、分页或选词影响。
4. 不需绑定共享词库。原“同步所选词语”仍只做词条增量；“绑定共享词库”是不同的长期共享管理操作。
5. 手机开启个人数据同步并联网后接收。词语/习惯分别显示能力、待应用数量和确认时间；旧手机需升级。服务器排队不是手机已接收，接收成功也不代替实际候选验收。
6. 两个后台的词条取并集；真实习惯按原始来源手机+输入码+词语去重，同一份备份重复同步不增加次数，原始使用时间不改为下载时间。用户本机学习记录不被覆盖或冒充远端点击；公共词频不混入个人次数。
7. 未记录拼音时不猜读音，不能直接添加拼音词条；合法输入码的真实习惯仍能下发，但候选能否显示还取决于匹配与有效读音/词库依据。明确停用记录不会因同步自动恢复。

### 内置公共词库

新包在原词库上合入固定版本 AOSP 拼音输入法词库，随 APK 离线使用；来源/许可/过滤及重现命令见 `android/YuyanIme/tools/data/t9-lexicon-sources.md`。公共词库和个人习惯是两层数据，不因“内置词较多”重置个人排序。当前不包含拼音纠错。

## 2026-09-28 核验：线上、换手机与换服务器

本节是只读核验结果及迁移边界，不代表已执行迁移或完成灾难恢复演练。

### 线上实际保存范围

2026-09-28 只读查询线上 PostgreSQL：荣耀 200（设备尾号 `6ad7605b`）有 7,302 条来源记录，其中选词记录 4,313 条、读音记录 2,989 条，合计去重词语 4,038 个；最近上报为北京时间 22:24:10。所属词库组另有 2 条删除规则和 1 条后台手工读音记录。记录数不等于词数，也不等于手机全部原生记忆。

本地先前核验的 5,373 条是 9 月 22 日的备份，两端各自接收手机上报，不是自动互相复制的数据库。手机导出只含本机来源的学习和读音，下载层不会再次冒充本机学习上传；原生 Rime 用户库也尚未完整导出。因此不能用手机现存数据重新上传来保证重建任意一端的全部后台数据。

线上当时尚无 `candidate_policy_supported` 字段，故全来源屏蔽新功能尚未部署，不能把旧管理快照确认当成新能力生效。

### 换手机

1. 旧手机联网同步，确认主后台的最近上报时间，再保留旧手机数据直至验收完成。
2. 新手机独立注册，不复制旧设备编号、同步凭据或整个 `local_input.db`。
3. 在主后台把新手机绑定到旧手机所属词库组，以继承显式删除/停用规则及已上报的共享学习记录。
4. 再向新手机执行“一键同步全部习惯和词语”，涵盖后台手工词等增量记录；仅增量发送不会自动建立删除规则的共享关系。
5. 新手机完成快照及增量确认后，实际验证常用词优先、已删除词不出现。原生独立记忆、尚未上报数据不在完整恢复保证之内。

### 换服务器

- 同服务器重新部署代码且保留原 PostgreSQL 数据：个人词库不依赖发布目录，正常部署不会清空这些表。
- 换服务器但仍用原域名：迁移完整数据库、数据库角色/权限与运行配置，保留原设备身份、凭据哈希、词库组、原始记录、手工词、删除规则和投递游标/序列；验证后才切流量。整个项目还需要迁移共享上传目录，词库表不是全项目备份。
- 同时更换域名：除数据库恢复，还需要旧地址在过渡期可达并向手机发布新地址；旧地址彻底失效时，已安装手机不能凭空发现新域名。
- 只克隆 Git 并创建空数据库：只能恢复代码和随版本携带的公共资源，不能恢复个人数据。旧手机可能补传自己的原始学习，但不会补传完整后台删除策略、下载层、其他设备来源或后台所有手工词。尤其不能保证新手机还能继承旧禁词。

### 已确认的备份及缺口

线上有部署前 `pg_dump -Fc` 备份，通常保留最近 5 份，保存在同一服务器 `/data/phpwww/shurufa/backups`。检查时最新文件为 `20260928T113729-21c3eed7dafa.dump`，约北京时间 19:42 生成；`pg_restore -l` 确认其中有全部七张 `dictionary_*` 表的数据条目。目录检查不是完整恢复测试，该备份也不包含其后新增的学习。

尚未验证异机备份、定时备份与完整恢复演练。服务器整机或磁盘丢失时，同机备份不能作为充分保障。正式迁移需要迁移窗口内的最新一致性备份、可用的异机副本，并在隔离环境恢复后核对记录、规则、游标与手机同步；不能以“重新部署成功”作为个人词库迁移成功。

2026-09-28 用户确认迁移时自行备份，本轮不执行真实备份、不配置定时或异机备份。迁移的数据归属、外来词副本、原生学习以及切换与验收要求见 [个人词库手动迁移设计](../plans/2026-09-28-personal-dictionary-migration-design.md)。其中外来副本完整上报与原生学习快照是待接入能力，不能将设计文档视为功能已经上线。
