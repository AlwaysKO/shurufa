# 微信识别、会话归类及图库修复（2026-09-21）

## 用户确认的范围
- 微信“发现”页不进入采集；微信首页、朋友圈继续采集并稳定归类。本条取代先前把微信首页、朋友圈作为非聊天页排除的单次实现，不扩大其他App的采集范围。
- “对方正在输入”是当前聊天人的临时状态，不作为新联系人。无法可靠确认联系人时仍保留首图，不凭相似名字跨人合并。
- 后台桌面图库5列，每页最多20张图片，数字页码、首末页与跳页；小屏自适应。
- 合并/确认来源归属及合并面板使用统一按钮样式。不代用户操作实际记录。

## 原因与改动
1. OCR标题噪声过滤/页面排除依赖精确文字，错字可绕过；微信首页原本被排除。新增固定页面别名白名单（朋友圈/朋友屠/用友殿/田友殿，微信/微佳，发现/发机），只对微信固定页面链路处理。精确标题字形可缓存固定类别，后续同字形的新OCR拼写沿用类别，不做近似像素或全局姓名匹配。
2. 临时状态原先只兼容少量末尾标点，且截图等待期间原始标题变化会被当作换人。补齐空格/冒号等变体，保留同一导航代次、同窗口的身份；导航后不复用前一联系人。
3. 未确认名字原先遇到一个OCR字符抖动就重置投票；微信仅在独立时刻的精确字形相同且只差一个字符时继续确认，不把不同字形/相似姓名当一个人。已确认名字不因一次错读被覆盖。
4. 固定页面支持空树OCR与可读树两条采集路径，不要求输入框。已存首帧识别为固定页面时原key升级，不把首图遗留在待确认；无标题裁剪的固定页面截图失败也有限重试，不产生空占位记录。
5. 历史固定页面错字在服务端查询时归一（限定微信wechat-empty-tree来源），读取、导航、删除组范围使用同一名称表达式；不更新历史原始名称、不物理合并/删除数据。明确is_pending_source=false优先于旧前端低置信度启发式。
6. 旧分页按消息数计，一条消息多张图会超过每页数量；图库模式先展开唯一图片关联再分页，缩略图与原图同资产不重复。纯文字和混合非图片附件保留独立项，所以界面明确显示“项（图片逐张分页）”。旧消息接口模式保留，图片导航仍跳过非图片项。
7. 新增5列响应式布局、较大缩略图、数字页码/省略号/首页末页/跳页，以及合并、来源、目标、搜索、取消、合并目标分页按钮的边框、背景、圆角和交互状态。
