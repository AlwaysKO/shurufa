## 最小样本提取

仅从既有导出中提取指定设备窗口的53个纠正片段，保留选中文字、输入码、替换词及类型；不复制完整编辑正文、会话名、设备 UUID 或截图。材料在被 Git 忽略的 `.runtime/input-correction/`，不纳入源码。提取程序只读取远端文件，将结果写入本地。

29个局部/位置变化样本中，只有17个满足：旧上屏位置唯一、重新上屏位置明确、原词保留非空前缀、删除后输入框等于该前缀和原有上下文。这是结构证据，不代表17个全是错选，更不代表读音边界都可确证。

可用最短调查例：

- `326242` 倒插，保留“倒”，以 `242` 换为“茶”。
- `526744` 老是，保留“老”，以 `744` 换为“师”。
- `966243` 我那个，保留“我”，以 `6243` 换为“哪个”。

实现仍应在实际 T9 提交音节、按键边界和原奖励凭据明确时撤回错误后缀对应的本次奖励；不能仅凭后端文本反查拼音，不能将保留前缀重奖，也不能把输入码变动自动当作错误。

重输含正常改写的可能；“可检验目标”只用于候选是否能出现的诊断，不能断言原候选一定错。另一个更长码的重输位置发生变化，未强行拼接目标整句。

`.runtime/input-correction/InputCorrectionReplayTest.kt` 使用正式 OfflineT9Candidates、真实主词库/领域词库/公开词索引/补全索引，以空个人库检查上述样本和少量明确同码例。分别观察无原生数组的本地召回名次、已提供准确原生文字与读音时的保留结果。

名次为0起始，-1只表示本次 firstPage 未出现。注入目标只验证过滤是否接受，不能当作实际引擎会产生目标的证据；空个人库不能恢复当时用户排序。现有321条公开回放来自固定开源 C API 候选，并非当前手机闭源 JNI 的现场录制。

当前没有历史前几项候选与选择来源，仍需新诊断区分召回、排序、分词和误触。不得根据这些片段直接调高某几个词的全局权重。
