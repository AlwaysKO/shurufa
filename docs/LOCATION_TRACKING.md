# 位置、Wi-Fi 与停留记录

## 开启均衡记录

安装包含此功能的新版 APK，打开「设置 → 其他」：

1. 开启「个人数据同步」与「位置采集」。
2. 开启手机系统定位，再开启「均衡位置记录」，按系统提示授予定位权限。读取 Wi-Fi 名称需要精确位置权限；只有大概位置时可能无法读取。
3. 允许通知后，可在定位常驻通知中停止均衡记录，也可回设置关闭。

均衡模式移动时目标约 30 秒采样，观察到稳定停留后改为约 5 分钟请求新定位。重新移动时可由被动定位提前唤醒，否则通常需要等待下一次低频定位；系统省电、无信号等可能延长间隔。系统结束该服务后需要回设置重新开启，不承诺全天不间断。

**位置没有有效变化就不上报。** 普通采集和均衡模式均如此，不发静止位置心跳。首次有效位置允许记录；随后与上次成功进入本地队列的记录比较，位移必须超过 50 米且超过前后两次定位精度之和，以过滤原地漂移。Wi-Fi、电量、速度或精度单独变化不触发位置上报；已在离线队列中的报告仍正常补传。此规则按用户 2026-09-29 最新要求，取代此前静止心跳方案。

关闭均衡模式后恢复原来的输入法机会定位；关闭「位置采集」停止位置采集；关闭「个人数据同步」停止总采集和发送。离线时复用现有本地持久队列，恢复连接后补传。

## 后台可以查看什么

在「设备与数据 → 位置轨迹」默认查看北京时间当天，可按设备、前一天、后一天或指定日期查看：

- 已连接 Wi-Fi 的名称、热点标识、信号、频率和链路速率（不是实际下载速度）。不扫描附近 Wi-Fi，也不记录密码。
- 定位时的网络类型、电量、是否充电、亮屏或熄屏、省电状态。系统提供时显示定位高度、移动方向、速度误差；定位高度不能用来判断楼层。
- 估算停留：同一区域至少 5 分钟的连续观测跨度，不把最后一条记录延伸到当前时间。
- Wi-Fi 观测跨度：采样中连续观察到同名网络及相同热点标识的跨度。热点标识缺失时仅说明名称一致，不保证中途一直连接，也不等于实际在场时长。
- 路线段与估算里程：按设备、北京时间日期、超过 15 分钟的缺口和明显跳点分段。停留内部漂移不累计里程。显示采样点之间的连线，不是沿道路还原的导航路线。

历史记录未采集的字段显示「未采集」，不会从旧坐标补造历史 Wi-Fi。未连接、权限不足、系统定位关闭和信息不可读取分别显示。

页面最多加载所选日期最近 1000 个点，超过时明确提示仅分析已加载记录。估算停留和里程不代表完整行程；只有一个点不能证明停留时长，长时间没有记录也不能证明一直在原地。位置不变不上报后，后台不会有静止期间的连续新采样，不能据此给出精确停留或 Wi-Fi 持续连接时长；有足够连续证据的历史记录仍可展示原有估算。

## 部署与验证边界

服务端需要 `034_location_context.sql`，旧手机没有 `context` 字段仍可上报。新信息需要更新 Android 客户端后产生。后台修改本身无法让旧 APK 采集 Wi-Fi。

本次本地验证包含手机策略/服务模拟测试、服务端接口测试、本地 PostgreSQL 临时表写入/读取/幂等验证、前端分析/组件测试及浏览器夹具。它们不代替实际手机上的权限、息屏轨迹、定位精度或耗电验收。
