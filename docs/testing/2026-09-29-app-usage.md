# 2026-09-29 应用使用记录：验证与交付

## 功能与口径

- 本地后台入口：`/app-usage`。原 `/apps` 输入字符分布保持不变。
- 按手机、App、含具体时刻的范围查询；总时长、已结束段次数、排行、北京时间每日分摊、分页明细、独立全天时间轴。
- 全天轴不依赖明细页，最多绘制 2000 段，超过时显示真实总数与截断提示。断档不计使用，App 筛选也保留断档。
- “最近收到记录”是设备整体最近入库时间，不证明实时采集或全部同步完成。
- 手机「设置 → 其他 → 应用使用记录」默认关闭；需个人数据同步同意和系统“使用情况访问权限”。明确告知包名/应用名/起止时间双端保存，不读取页面内容。
- 从开启时开始，不导入授权前历史。切换、PAUSE、熄屏、锁屏结束前台段；同 App Activity 短切换合并。分屏采用最后恢复的应用单一归属，不等同系统屏幕使用报告的所有口径。
- PAUSE 与 STOP 分开：公开系统接口没有实例 ID，迟到 STOP 不得截断同类新实例。锁屏期间明确 RESUME 且尚未 PAUSE 的候选在解锁/亮屏时才开始计时。
- 系统事件查询保留 5 秒稳定尾部，缓解异步入库；这不是 Android/OEM 保证的最大迟到时间。进程存活时约 30 秒轮询，独立系统 Job 约 15 分钟调度，省电/强行停止可进一步延迟。
- 超过 24 小时未查询的旧部分、已知权限/查询中断、启动标识变化采用保守断档；无可靠 boot counter 时冷启动不拼接旧 active。只上传已结束段，不伪造持续使用。
- SQLite 将游标、候选和每端待传记录原子保存；仅明确匹配回执后确认该端。完全确认的记录本地保留 7 天，未确认记录不因保留期被删除。
- 关闭先取消调度及已登记的网络 Call（包括尚未 execute 的 Call）；数据库异常不能使关闭失效。开启则必须先保存基线。已经到达服务端的请求不能被客户端撤回。

## 复跑方式

```bash
cd server
APP_USAGE_TEST_CLUSTER=<独立测试实例目录> npx vitest run src/api/appUsage.postgres.test.ts
npm run build
cd ../client
../server/node_modules/.bin/vitest run tests/app-usage.test.ts
npm run build
```

PostgreSQL 测试仅使用独立临时实例：目录须为 `/tmp/shurufa-app-usage.*`，`test-instance-only` 文件内容严格为 `app-usage-only`，Unix socket 位于该目录 `socket`，数据库 `app_usage_test`、角色 `ko`；测试会校验 `data_directory` 为该目录 `data` 后安装迁移。不指向真实开发库/线上库运行测试数据清理。
