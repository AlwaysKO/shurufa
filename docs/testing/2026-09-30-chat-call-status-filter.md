# 聊天采集通话状态过滤验收

## 范围与根因

用户截图中的“待确认会话”显示通知正文“语音通话中”，消息类型 voice。旧 NotificationParser 专门将通话前缀分类为语音/视频并请求补截图；服务端只做 5 分钟重复通知去重，因此状态会持续入库。

本轮精确过滤通知正文“语音通话中”“视频通话中”，微信/QQ/抖音共用规则；不按联系人名、voice 类型或“通话”关键词泛化。普通 `[语音]`、含类似文字的完整句子、UI 来源正文和明确 MessagingStyle 消息继续保留。

## 实现

- 新通知在 shouldIgnore 阶段结束，不解析入库、不唤醒媒体或隐藏通知补截图。
- 新通知保存 notification_messaging_style；旧队列中该字段缺失时，兼容旧 notification_message_timestamp 正整数标记，防止误丢真实聊天文字。Android 与服务端均按此规则判断；真实消息也不进入旧通话状态去重。
- CaptureApi 在 Room 队列消息转发前过滤；EventDelivery 在通用持久报告队列实际发送前再次过滤，涵盖已经积压的状态正文。全状态批次不发送聊天 HTTP；取消通用队列任务时不写 online_confirmed_at。混合批次只上传保留项，失败仍保留并在重试时再次过滤。
- 服务端在建会话、素材查找前过滤，兼容尚未升级的手机；全状态批次返回 200、ok=true、inserted=0、missingAssets=[]，不创建空待确认会话，不触发无限重传。

## 素材及历史边界

- 不清理服务端历史记录；不会把“禁止新上报”解释成删除用户数据。
- 新状态不触发补截图。旧版已生成的独立截图没有可靠通话关联，本轮不追溯删除；可能共用的素材继续遵循原有 Wi-Fi、熄屏及输入避让约束。
- 如果旧状态消息已有素材依赖，现有上传链仍先处理素材，消息就绪后过滤正文。本轮不承诺取消这些既有素材上传；服务器过滤旧状态后不会再索要其素材。审查指出该限制，已收窄验收声明，没有将队列素材清理作为已完成事项。
