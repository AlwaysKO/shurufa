# 聊天图片的采集与接收时间

用户反馈凌晨图片白天才上传，单一时间容易误读，要求优先显示截图时间或并列显示两个时间。

核对结果：聊天采集页原本使用 chat_message.captured_at，并按该时间倒序分页，但显示缺乏明确标签，且跟随浏览器本地时区；未关联图片页使用 media_asset.created_at。线上只读样本为2026-10-28 01:15:03采集、12:32:32图片入库、12:32:35聊天记录入库（北京时间），三个时间不同。

实现：

- 已关联图片卡片、首次原图预览及跨页切图同时显示“截图/采集”和“上传接收”，统一Asia/Shanghai并精确到秒。会话名不再附加一份无标签时间。
- 截图/采集沿用手机上报的 captured_at；不是图片内聊天文字的发送时间或任意图片的EXIF时间。排序仍按 captured_at，未改历史数据。
- 上传接收来自各图片 media_asset.created_at，表示当前资源记录的首次入库。同手机同内容去重复用资源时不刷新；不使用较晚到达的 chat_message.created_at，也不推断每次重传时间。
- 未关联图片没有可信采集时间来源，在卡片和原图中明确显示“截图/采集：未知（未关联）”与“上传接收”。不从文件时间、服务器接收时间或图片内容猜测采集时间。其现有日期筛选、保留清理仍按接收时间。
- 无数据库迁移，无Android采集/上传变更，无线上记录修改。

验证：

- 前后端构建通过；聊天组件、图片API客户端、消息列表API共120项相关测试验证通过。
- 独立PostgreSQL实例执行6项受影响的读取测试：两种列表、跨页相邻图、设备隔离、捕获/图片/记录接收时间区分，延迟上传不改变排序。
- 专项浏览器测试在1440px/UTC与390px/洛杉矶时区下显示同一北京时间，验证原图前后切换、缺失接收时间显示未知及360px短窗口布局。
- 未关联图片浏览器回归在1440px与390px通过，删除/清理测试仅用合成数据。
