# 待确认聊天来源删除与归属验收

用户明确“归档”指归到正确联系人/群聊下，不是隐藏到独立归档列表。

## 完成范围

- 待确认分组每个实际来源均有“删除此来源”，支持纯文字、语音提示及图片来源。先读取最新来源编号、消息数量和名称，再由页面弹窗确认；不允许删除整个虚拟 id=-1 分组。
- 删除接口通过 pending_only、platform 在事务内重新核对当前用户、App、未确认及未合并状态。确认过程中来源已变化则拒绝，避免误删已确认来源或合并目标。完成后同步刷新消息、列表与统计。
- 归属面板继续支持合并到已有会话；没有已有目标时可填写联系人/群聊名称直接确认该来源，保留所有消息并移出待确认组，不按相同名称物理合并其他来源。
- 人工确认名称与置信度不再被后续采集上报降级/改写；查询时人工名称跳过历史 OCR 别名映射。建议归属入口使用当前来源标题初始化输入，不残留另一来源的名称。

- 服务端仓库/聊天 API 普通回归 **40/40**，前后端构建通过。前端保留原有 bundle 大小提示。
- Chromium 使用本地实际 API 和本地数据库的合成设备/两个来源，实测取消删除、纯文字删除、其他来源保留、无目标命名后移出待确认列表，以及点击已确认会话仍有正文。0 pageerror。合成数据已按唯一设备 ID 清理。
