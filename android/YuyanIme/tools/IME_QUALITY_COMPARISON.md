# 搜狗与 shurufa 候选对照

`data/ime-quality-cases.json` 是人工候选回归集，覆盖24个词的70种输入。
目标词用于检查是否容易找到，不要求歧义输入都把该词放第一；该集合不能证明大众词频或整体输入质量。
同一词的所有变体放在同一分组：development 用于调查，holdout 保留到改动完成后检查。

## 实际观察

在独立空白测试编辑框中分别切换两款输入法，记录版本、设备、网络和学习状态。
不清除用户数据；已有个人学习的手机只能代表当前状态，不能称为全新用户基线。
每个用例从空组合输入开始，按 `actions` 操作：

- `keys`：实际点击对应键盘按键；数字使用中文九宫格，字母使用中文全键盘。
- `lock_pinyin`：点击左侧对应拼音选项。无该选项或未完成任何动作时，将用例 ID、失败动作与截图单列到执行失败记录，不放入 `observations`。未锁音的候选不能冒充锁音后的候选参与比较。
- 记录相同范围的候选（建议前10个）和截图，再取消组合输入。候选不足时记录实际个数。

不能用 `adb input text`、编辑框 `setText` 或直接传汉字代替键盘操作，它们绕过输入解码。
本批不自动选词，避免用测试反复训练词序；提交/退格/联想需要另测。
屏幕坐标必须按两款输入法当前布局实测，不能套用另一设备的坐标。

## 数据格式与比较

两份 JSON 各自包含 `metadata` 和 `observations`。格式示例（仅说明格式，非实测结果）：

```json
{
  "metadata": {
    "ime": "输入法名称",
    "version": "实际版本",
    "device": "机型与系统版本",
    "network": "实际联网状态",
    "learning_state": "保留已有学习，未清除数据"
  },
  "observations": [
    {
      "id": "01-t9-locked",
      "candidates": ["按实际显示顺序填写"],
      "evidence": "原始截图路径"
    }
  ]
}
```

```sh
python3 compare_ime_candidates.py sogou-observations.json shurufa-observations.json > comparison.json
python3 -m unittest test_compare_ime_candidates.py
```

输出含两边共同实测用例的 top1/top3/top5 比例、按输入类型与保留分组的结果、逐项排名以及缺失观测清单。
空候选数组代表已经观察且确无候选；没有观测不能填空数组代替。
截图、观测和报告放项目忽略目录 `.runtime/input-quality-20261013/`，不提交个人数据。
工具只处理观测文件，不连接手机，也不确认文件内容是否真实；结论必须核对原始证据。

只有在相同条件的实际对照中定位差距，才决定改召回、分词或排序。
修改后重测保留分组和现有输入回归，不能只汇报提升的用例。
