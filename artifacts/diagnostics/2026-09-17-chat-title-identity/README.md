# 微信截图标题识别稳定性修复（2026-09-17）

## 范围与安全边界

- Android 空无障碍树的微信截图分支；不改 QQ/抖音适配规则，不更换 OCR 引擎、不向外部服务发送图片。
- 新版使用 `screenshot-v2:` 字形签名作为初始独立标识，显示名与标识分开。旧 `title:` 记录不回写、不合并、不删除；同一个人升级前后的记录可能分别处于旧、新会话，不能声称升级会自动修复历史拆分。
- 标题区域保留完整字形分辨率，去空白后二值化再 SHA-256；不使用低分辨率感知哈希的近似距离来自动合并名字。
- 连续页面中：字形签名完全相同允许 OCR 文本抖动；规范化标题文字完全相同允许截图压缩或群人数改变。页面切换、离开应用、超时等不再沿用后一种连续性假设。
- 两次间隔至少350ms的一致识别才确认名称。首次未确认时最多补看两帧（每帧间隔800ms）。单次错字不更改已确认名称。
- 导航/锁屏/授权撤回检查与识别版本号阻止迟到 OCR 污染新会话；补看帧身份不同，不能把第一张图片归入第二位联系人。
- 不可确认的截图用待确认名称保留；低置信度保留例外只适用于指定微信分支、独立标识、图片资产和明确 pending 元数据，其他采集的置信度门槛不变。
- 服务端只保护新 `screenshot-v2:` 名称不被迟到的低置信度上传降级；按明确标识入库，不进行相似名称搜索/合并。

## 已知限制与验收要求

- 仍是端侧 Google ML Kit OCR + 页面证据，不拥有微信联系人真实唯一ID；不能保证同名且显示字形完全相同的不同联系人可区分。
- 字体、主题、布局或压缩使字形签名改变，且不具备连续页面证据时，宁可重新待确认，不进行有串聊风险的全局模糊合并。
- 置信度0.55/0.85是本地分组证据等级，不是 OCR 准确率。
- 真机实际识别效果须安装新版后由用户操作验证；不能以合成图像和单元测试代替真实手机验收。
