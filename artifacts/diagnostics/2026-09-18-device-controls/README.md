# 手机删除与上报保存开关 — 2026-09-18

## 已确认规则

- 后台“选择用户”每行新增“保存上报数据”开关和删除按钮；默认保存。关闭需确认不保存的后果，开启直接恢复。
- 关闭时已知上报入口仍成功应答，事件/聊天/位置/词句/用量/词库正文不保存，聊天附件不写业务上传目录。持久化报告回执保留客户端提交的ID，聊天成功响应无缺失附件错误。
- 判定以服务器处理新上报请求时的状态为准；已经进入处理的请求不追溯撤销。服务器不缓存或恢复已丢弃内容。手机本地数据不受影响，未来主动全量同步或再次上报仍是新请求，不承诺阻止手机重新上传本地历史。
- 保留恢复管理所需的最小设备ID/开关和词库控制凭据；关闭期间不刷新手机上报的名称、型号等详情。查询及词库登记继续可用。
- 删除精确目标手机当前数据与设备行，保留独立 `runtime_setting.device_save_uploads:<id>` 开关；不封禁，后续注册或新上报仍可出现；即使客户端缓存“已注册”不再注册，也能恢复最小目录行并沿用原开关。
- 系统自定义确认窗口：显示名称、设备ID、范围、不可恢复提示；Enter确认、Esc取消。取消/失败保留列表，重复点击被阻止，当前用户删除后重新选择，最后一条删除显示空态，末页回退；异步响应不能抢回已切换的用户。

## 删除与文件安全

- 使用显式业务表清单及精确user_id/device_id，事务锁定后删除。输入/位置/聊天/关系与AI记录、个人词句/候选/统计/上报回执、个人图与词库记录、分析游标纳入范围。
- 不删除系统素材、其他手机数据、仍被使用的词库共享组策略。异常跨用户会话/附件引用直接409并回滚。
- 数据库事务先写精确文件清理任务再提交；提交前不操作文件。之后复核所有手机引用，只有无引用的合法 uploads/chat、stickers、synthesis 路径才删除，拒绝越界目录和异常路径。
- 聊天文件上传先取得匹配数据库锁再落盘，防止内容寻址文件清理与新上传交错。失败文件任务持久化在runtime_setting，启动时及每60秒重试；前端明确提示“数据库记录已删除，附件待重试”。既有记录回滚时不会丢图。
- 没有新增迁移；依赖已有020运行配置表。旧库缺少020时默认仍保存，控制接口不伪装成功。部署前需保证既有迁移完整，使用现有入口启动后端以启用附件重试任务。
