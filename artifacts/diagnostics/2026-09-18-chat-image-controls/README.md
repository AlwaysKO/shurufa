# 聊天图片浏览与本页批量删除（2026-09-18）

## 已确认范围与实现
- 微信/QQ/抖音使用同一逻辑：放大后支持按钮、键盘左右、鼠标拖动、触摸滑动，Esc关闭；当前会话图片按消息captured_at DESC、id DESC及附件position/id正序浏览，跨列表页、不跨会话，跳过无图片消息。同一消息/资源的多role不重复作为相邻图。
- 新GET /chat/images/adjacent使用消息ID/资源ID锚点，只返回相邻一张的元数据，前端不一次下载整个会话图片；边界不循环，加载互斥、失败重试、关闭/切换后忽略迟到响应。预览焦点保持/恢复、背景inert、Tab限制；导航按钮禁用前焦点回弹层，修复真实浏览器发现的Esc失效。
- 本页筛选后可见图片逐张勾选、全选本页、全不选、删除选中；以message_id+asset_id标识，保留一条消息多图及跨消息同图的明确关联。翻页/筛选/会话/App/用户变化清空选择并关闭预览。每批最多1000图片关联。
- POST /chat/images/delete-batch限制当前用户与明确会话，要求DELETE确认和去重后的精确关联；事务锁定核验整批，删除选中关联，保留文字、未选图片及其他会话/用户。只有删空的image类型消息且text为NULL/空/既有“图片”“截图”占位才清理空行。
- 共享资源仍有任何消息引用则保留；无引用资产删除后，在同事务内校验路径并保存精确文件清理任务；提交后再次检查所有用户/素材的共享路径，只删不再使用的文件。复用现有持久化任务及后台重试；磁盘失败返回files_pending并明确提示，不冒称数据库回滚。
- 为避免并发同内容上传读到将删除的旧资产ID，按与设备删除一致的表顺序加锁，与storeAsset写锁互斥。新增并发回归证实修复前返回旧ID、修复后新上传保留有效新ID与文件。
- 原有单张图片与会话删除接口保留；此次未扩展其既有物理文件清理逻辑。未修改Android或采集规则。
