# 音节输入中途出现键帽标签：显示修复验收

## 用户复现与根因范围

用户报告“我当时想输入”前面全拼，输入 s 时出现类似 `〔PQRS/GHI…〕` 的字母组，继续 h 后消失。此前截图另有 `fo'lao'〔MNO TUV…〕`，其原始目标未确认；测试中的 `365266885699` 只是从图示拼音/键帽推算的码，不冒充原始输入记录。

已确认显示函数把候选未覆盖的残码展开成键帽列表，所以只要某一帧缺少覆盖末尾的读音，就会触发这种显示。**手机 ADB 不在线，未确认那一帧原生候选为何缺少完整读音。** 独立开源 Rime 1.11.2 的19步输出有 s/sh 对齐读音，未复现手机这帧异常，不能将其当作 APK 原生复现；原始输出见 `host.tsv` / `host.log`。

## 实际改动

仅两个生产文件：`T9Spelling.kt` 的显示兜底与 `T9PinYinUtils.kt` 的只读拼读辅助。精确增量见 `scope.patch`。

- 实际候选读音仍优先，已有完整首选读音不变。
- 暂无读音的残码按既有 T9 拼音表显示一种等价拼读；内部完整音节、末尾可为声母，不展开键帽，不丢键或扩写按键。
- 不能组成音节的极端码串保留等价的小写单键代表字母，**不声称它已成为正常拼音或完整句子**。
- 九宫格存在歧义：没有实际读音时，7→74→748 按既有表可显示 p→pi→qiu，不保证猜中用户意图 s→sh→shu；候选实际读音一到即优先使用。不会为迎合个案改表顺序或加入词条。
- 显示结果不回写原始组合、候选、提交或学习。即使显示看起来完整，原始未消费码的提交保护仍有效。
- 每个位置最多检查6种长度，无递归或组合枚举；但路径保存完整后缀字符串，字符复制/驻留为 O(n²)，不声称严格线性。

23套件131项，0失败/错误/跳过；最终构建成功，见 `final-build.log.gz` 和 `final-xml/`。
